GitHub for Interactive Storytelling

GitHub is where students can store project files, track changes, and publish simple HTML/CSS/JavaScript projects to the web using GitHub Pages.

Core idea: GitHub is not the design tool. VS Code is where you edit files. Git tracks changes. GitHub stores the project online. GitHub Pages publishes the project as a website.

What GitHub does, and what students do

Students do not need to become software developers to use GitHub for this course. They do need to understand the file workflow well enough to avoid losing work and to publish updates.

The responsibility split

GitHub helps with storage, version history, collaboration, and web publishing. It does not fix broken files, organize assets, or decide what belongs in the project.

Workflow basics

VS Code

The editor. This is where students open the project folder and change HTML, CSS, JavaScript, images, and other files.

Git

The tracking system. Git records snapshots of the project when students commit changes.

GitHub

The online home for the repository. GitHub stores the project and can publish it with GitHub Pages.

RepositoryThe project folder as tracked by Git and stored on GitHub.
CommitA saved snapshot with a short message explaining what changed.
PushSending local commits from VS Code to GitHub.
PullBringing changes from GitHub back down to the local project.
BranchA version line of the project. For this class, students will usually use main.
GitHub PagesA publishing feature that turns repository files into a public website.

Creating a GitHub account

Students need a personal GitHub account before they can create repositories, push work from VS Code, or publish with GitHub Pages.

Account setup steps

The account should be tied to an email address the student can access and verify.

One-time setup
  1. Go to GitHub and sign up. Use a username that is appropriate to appear in project URLs, portfolio links, and public repositories.
  2. Use an email address you can access. GitHub requires email verification for basic account tasks.
  3. Save your password and enable security prompts. Students should not share their GitHub password with AI tools, classmates, or copied code.
  4. Use the same account in VS Code. When VS Code asks to sign in to GitHub, use the account that owns the class repositories.

Teaching note: Account names become part of many GitHub Pages URLs. A professional or neutral username is safer than a joke username.

Before class work begins

Students should confirm these pieces before trying to publish a project.

Checklist

Account checks

  • Can sign in to GitHub.
  • Email address is verified.
  • Username is acceptable for public project links.
  • Knows whether the repository should be public or private.

Computer checks

  • VS Code is installed or available in the lab.
  • The project folder is easy to find.
  • Files are saved locally before committing.
  • Images and other assets are inside the project folder.

Setting up the project in VS Code

A GitHub project works best when students start with a clean folder and keep all required files inside it.

Recommended project folder

For a simple interactive web project, the folder can stay plain: one HTML file, one CSS file, one JavaScript file, and asset folders.

Local files 
interactive-storytelling-project/
├── index.html
├── css/
│   └── styles.css
├── js/
│   └── script.js
├── img/
│   ├── hero.jpg
│   └── diagram.jpg
└── data/
    └── birds.json

Important: GitHub Pages needs an index.html file at the publishing location. For the simplest workflow, put index.html at the top level of the repository.

Open the folder in VS Code

Students should open the whole project folder, not just one file. The Source Control panel needs to see the project as a folder.

VS Code
  1. Create or locate the project folder. Put it somewhere stable, such as the Desktop or Documents folder. Do not work from downloads, email attachments, or temporary folders.
  2. Open VS Code. Choose File → Open Folder, then select the project folder.
  3. Create or add project files. At minimum, a simple page needs index.html. CSS and JavaScript can be separate files or included in the HTML while students are learning.
  4. Preview locally. Open index.html in the browser or use a local preview extension if available.

Create the repository from VS Code

Students can publish the folder to GitHub through VS Code instead of using the command line.

Initial publish
  1. Open the Source Control panel. In VS Code, use the branch/source-control icon in the left activity bar.
  2. Initialize repository. If the folder is not already a Git repository, choose Initialize Repository.
  3. Add a commit message. Use a clear message such as Initial project setup.
  4. Commit the files. VS Code may ask whether to stage all changes. Choose yes for the first commit.
  5. Publish Branch. Choose Publish Branch and sign in to GitHub if prompted.
  6. Choose public or private. For GitHub Pages, public is usually simplest for student websites. Private repositories may require plan or setting considerations.

Safer first repository name: Use lowercase letters, numbers, and hyphens: interactive-project-1. Avoid spaces and special characters.

Adding, committing, and pushing with VS Code

The everyday workflow is simple: save files, review changes, commit them, and push them to GitHub.

The repeatable workflow

Students should use this cycle every time they make meaningful progress.

Save → commit → push

1. Save

Save changed files in VS Code. Unsaved work is not ready to commit.

HTML CSS JS Images

2. Commit

Write a short message describing the change, then commit. A commit is a named checkpoint.

Good: Add hotspot annotations Weak: stuff Weak: final final fixed

3. Push

Push sends the committed checkpoint to GitHub. If they do not push, GitHub Pages may not update.

VS Code action What it means Student translation
Stage changes Select which file changes will be included in the next commit. “These are the changes I want to save in this checkpoint.”
Commit Create a local snapshot with a message. “Save this version of the project history.”
Push Send local commits to GitHub. “Upload my saved work to the online repository.”
Pull Bring online changes back to the local folder. “Get the newest version before I keep working.”

Common mistakes

Most beginner problems are file-location or workflow problems, not advanced coding problems.

Troubleshooting
Check filename case, folder paths, and whether files were pushed. GitHub Pages is case-sensitive. Img/photo.jpg and img/photo.jpg are not the same path.
The student may have committed locally but not pushed. In VS Code, check whether there is a Sync/Push button or outgoing changes.
Images must be inside the project folder and referenced with correct relative paths. Avoid linking to files on the local computer, such as /Users/name/Desktop/photo.jpg.
A conflict usually means the local project and GitHub both changed. Students should stop and ask for help rather than randomly accepting all changes.
That is not a major problem for class work. The bigger issue is failing to commit meaningful checkpoints before experimenting with AI-generated code.

Setting up GitHub Pages

GitHub Pages publishes the repository as a website. For class projects, the simplest setup is usually to publish from the main branch and the root folder.

Turn on GitHub Pages

This step happens on GitHub.com after the project has been pushed from VS Code.

Publishing
  1. Open the repository on GitHub.com. Use the same repository that VS Code pushed to.
  2. Go to Settings. The Settings tab is near the top of the repository page.
  3. Open Pages. In the left settings menu, choose Pages.
  4. Choose the source. Under Build and deployment, use Deploy from a branch.
  5. Select the branch and folder. Choose main and /(root), then save.
  6. Wait for the site to build. The first publish may take a little time. Refresh the Pages settings page to find the published URL.

Requirement: The repository needs an index.html file in the selected publishing folder. If Pages is set to main and /(root), index.html should be at the top level of the repository.

Find and test the published URL

Once GitHub Pages is active, students need to test the public link, not just the local file.

Live site

Common project URL pattern

For a regular project repository, the URL usually follows this shape:

https://username.github.io/repository-name/

What to test

  • The page loads from the GitHub Pages URL.
  • Images and videos appear.
  • Buttons, links, and interactions work.
  • The page works on a phone-width screen.
  • The URL can be opened by someone else.

Updating the published site

After Pages is turned on, the live site updates when students push new commits to the publishing branch.

Ongoing workflow
  1. Edit files in VS Code. Make changes to HTML, CSS, JavaScript, images, or data files.
  2. Preview locally. Check the page before committing.
  3. Commit with a useful message. Example: Fix mobile card layout.
  4. Push or sync changes. Send the commit to GitHub.
  5. Check the live URL. GitHub Pages may need a moment before the update appears.
Class rule: A project is not “turned in” just because it works on the student’s computer. It should work from the public GitHub Pages link.
