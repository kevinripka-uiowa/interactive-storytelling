Participate and Personalization

Participatory interactives ask viewers to make choices, enter information, test assumptions, draw, contribute, or follow a path. The interaction should change the result, reveal a consequence, or help the viewer understand something.

Two levels: interaction methods describe what viewers physically do. Participatory patterns describe what the story does with their input.

HTML form elements

Native HTML form controls collect common kinds of viewer input. Each control is designed for a different kind of answer, so the control should match the decision the viewer is making.

Native controls

Why use native controls?

  • Browsers already understand their meaning and expected behavior.
  • They usually work with keyboards, screen readers, and mobile devices without extra code.
  • Use a visible label that explains what the viewer should enter or choose.

Radio buttons

Use radio buttons when the viewer must choose exactly one option from a short list. Giving the buttons the same name makes them a single group.

Preferred setting

Checkboxes

Use checkboxes when the viewer may choose any number of options, including none. Each checkbox represents an independent yes-or-no choice.

Features wanted

Select menus

Use a select menu for one choice from a list that would take too much space as radio buttons. The available options remain controlled by the author.

Text inputs

Use a text input for a short, open response such as a name, location, search term, or brief answer. Do not use it when a controlled list would be clearer.

Text areas

Use a text area when the viewer may need several sentences. It allows a longer response and can be resized in most browsers.

Range sliders

Use a range slider for an approximate value within a known minimum and maximum. Show the current value because the slider position alone is not precise.

Date pickers

Use a date input when the viewer should select a calendar date. The browser supplies the date-picker interface, which may look different across devices.

Form output

Complete any fields and submit the form to see how the controls become usable values.

Enhanced form controls

JavaScript libraries can add search, autocomplete, and multiselect behavior to ordinary form controls. These are useful when native controls become slow or cumbersome.

Tom Select

Use carefully

  • Prefer native controls when the option list is short.
  • Autocomplete helps viewers locate one item in a long list.
  • A searchable multiselect helps viewers choose several items without displaying a very long checkbox list.
  • Test keyboard, screen-reader, and mobile behavior because the library replaces part of the browser’s native interface.

Autocomplete

Autocomplete filters a long list as the viewer types. The viewer still selects a controlled option rather than entering unrestricted text.

Searchable multiselect

A multiselect allows several controlled choices. Search is useful when the complete option list would be too long to scan.
