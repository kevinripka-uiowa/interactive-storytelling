Coding basics for interactive storytelling

You do not need to become a full-time programmer to make useful interactive elements. But you do need enough code literacy to edit embed codes, adjust builder snippets, make small style fixes, understand AI-assisted code, avoid breaking the page, and explain what your interactive is doing.

Core idea: code may come from a hosted tool, a builder, a library, a tutorial, an embed code, or AI. Wherever it comes from, you remain responsible for the content, structure, usability, accessibility, attribution, and final testing.

What are you responsible for on a web page?

Most student code work is not writing a full application from scratch. It is reading, editing, testing, and adapting code that came from a tool, an embed, a template, documentation, or AI.

Your responsibilities

These are the parts students should be able to evaluate whether the code came from a hosted tool, a builder, a tutorial, a class demo, or AI.

Code literacy
1

Structure

Does the page have a clear order? Are sections, headings, buttons, links, images, and labels used for the right jobs?

2

Content

Are the text, images, data, labels, sources, and examples accurate and appropriate for the story?

3

Appearance

Do the colors, type sizes, spacing, hierarchy, and layout make the element clear and readable?

4

Interaction

Does the user know what to click, tap, drag, scroll, or select? Does the interaction actually serve the story purpose?

5

Responsiveness

Does it work on a laptop and a phone? Does anything overflow, shrink too much, or require hover on mobile?

6

Accessibility

Can someone use it with keyboard controls? Are images described? Are buttons real buttons? Is color not the only cue?

Where students are likely to edit code

In this course, code literacy usually means making small, targeted changes to code that already exists. The source of the code changes what is safe to edit.

Common contexts

Embed codes

Hosted tools often give you an <iframe> or script embed. Students may need to edit width, height, border, loading behavior, or surrounding spacing.

Builder custom HTML blocks

Tools like Tilda, Shorthand, WordPress, or other builders may provide a block where students paste HTML, CSS, or JavaScript snippets.

Hosted files

A GitHub Pages, Netlify, or class-hosted file may include full HTML, CSS, and JavaScript. Students may edit content, styles, data arrays, or repeated sections.

Tool-generated code

Flourish, Datawrapper, maps, galleries, timelines, and other tools may expose settings, embed code, custom CSS, or small configuration snippets.

Library-based examples

Examples using D3, Leaflet, Pannellum, Mapbox, or similar libraries often require editing configuration, data paths, labels, and container sizes.

AI-assisted prototypes

AI can generate a starting point or help debug. Students still need to understand what layer they are changing and verify that the result works.

Working rule: do not paste every kind of code into every kind of place. A full HTML page, a custom HTML snippet, an iframe embed, and a library configuration are different things.

Code editing mindset

Small code edits work best when you can describe the intended behavior, identify which layer you are editing, make one change at a time, and test the result.

Workflow
  • Do not change everything at once. Make a specific edit: “Set this iframe to 100% width,” or “Make the cards one column on mobile.”
  • Keep the file organized. Label major sections with comments or ask AI to add comments so you can find them later.
  • Test after each change. Make one meaningful change, refresh the browser, and check desktop and mobile widths.
  • Know what layer you are editing. HTML changes structure/content. CSS changes appearance/layout. JavaScript changes behavior/data-driven interactions.
  • Use AI as a helper, not a replacement for checking. Ask it to explain code, isolate the smallest fix, or debug an error, then test the result yourself.

HTML: structure and meaning

HTML is the structure of the page. It tells the browser what each piece of content is: a heading, paragraph, image, link, button, section, list, table, or form control.

Simplified HTML syntax

Most HTML is made from elements. An element usually has an opening tag, content, and a closing tag.

Structure 
<section class="story-card">
  <h2>Migration route</h2>
  <p>Monarchs travel across multiple generations.</p>
  <button type="button">Show details</button>
</section>
  • <section> groups a meaningful part of the page.
  • class="story-card" gives CSS or JavaScript a name to target.
  • <h2> is a heading, not just big text.
  • <button> is for actions on the page. <a> is for links/navigation.

HTML terms to recognize

These are the terms you should be able to spot when you edit embed code, custom HTML, or AI-assisted code.

Vocabulary

Elements are the building blocks of HTML. Examples include <h1>, <p>, <img>, <button>, and <section>.

Attributes add information to an element. Examples include class, id, src, alt, href, and aria-label.

A class can be reused on many elements. An ID should be unique on the page. CSS and JavaScript often use classes and IDs to target specific parts of the page.

Nesting means one element is inside another. If the opening and closing tags get mixed up, the layout or interaction can break.

Semantic HTML means using the element that matches the job: headings for structure, buttons for actions, links for navigation, lists for grouped items, and tables for actual table data.

Use commented snippets you can duplicate

When your interactive has repeated elements, the safest workflow is to clearly mark the smallest chunk you can copy, paste, and edit. You can write these comments yourself or ask AI to add them.

Reusable chunks

For example, if you have a card-based interactive, ask for a comment like this:

<!-- START: Duplicate this whole article to add another bird card -->
<article class="species-card">
  <img src="img/warbler.jpg" alt="Bay-breasted Warbler on a branch">
  <h3>Bay-breasted Warbler</h3>
  <p>Look for the chestnut throat and buff sides in spring plumage.</p>
</article>
<!-- END: Duplicate this whole article to add another bird card -->
Prompt or request to use: “Add comments that show exactly which HTML block I should duplicate when I want to add another item. Also tell me which text, image path, alt text, and labels I should edit.”

CSS: appearance and layout

CSS controls how the page looks: color, typography, spacing, layout, borders, shadows, responsive behavior, and visual states like hover or focus.

Simplified CSS syntax

A CSS rule has a selector, curly braces, properties, and values.

Appearance 
.story-card {
  background: #fffdf7;
  color: #17211b;
  font-size: 18px;
  padding: 20px;
  border-radius: 16px;
}
  • .story-card is the selector. It targets HTML with class="story-card".
  • background, color, and font-size are properties.
  • #fffdf7, #17211b, and 18px are values.
  • Every property line should end with a semicolon.

The style attribute: CSS inside an HTML tag

The style attribute lets you put CSS directly on one HTML element. Students may see this often when editing iframe embeds or small snippets from builders, because the code may not have a full stylesheet available.

Inline CSS

Basic pattern

<iframe
  src="https://example.com/interactive"
  title="Interactive graphic"
  style="width:100%; height:650px; border:0;"
></iframe>
How to read it: everything inside style="..." is CSS. Each declaration uses a property, a colon, a value, and a semicolon.

What it is good for

  • Quick iframe sizing: set width, height, max-width, or aspect-ratio.
  • Small one-off fixes: remove a border, add margin, or center an element.
  • Embed cleanup: make a pasted iframe fit the story column instead of using a fixed width.
  • Testing: try a small visual change before moving it into the main CSS.

Common iframe edits

GoalInline style exampleWhy it helps
Make an iframe fill the available widthstyle="width:100%; border:0;"Prevents a fixed-width embed from overflowing the story column.
Set a taller embedstyle="width:100%; height:700px; border:0;"Useful for maps, timelines, or interactives that need vertical room.
Use a responsive video shapestyle="width:100%; aspect-ratio:16/9; height:auto; border:0;"Keeps video-style embeds proportional across screen sizes.
Add space around an embedstyle="margin:24px 0;"Creates breathing room before and after the embed.
Center a smaller itemstyle="display:block; margin:0 auto;"Makes an iframe, image, or block-level element sit in the center.

When not to use it

  • Do not use inline styles for repeated design systems. If many cards need the same style, use a class in the main CSS instead.
  • Do not put media queries inside a style attribute. Responsive rules like @media belong in the stylesheet, not inside style="".
  • Do not paste a full CSS block into the style attribute. The style attribute only accepts declarations like width:100%;, not selectors like .card { ... }.
  • Be careful with fixed heights. A height that works on desktop may be too tall or too short on a phone. Test the iframe at mobile widths.
Student strategy: use the style attribute for small, specific embed fixes. Use the main CSS when the change should apply to many elements or needs responsive rules.

Responsive CSS: desktop vs. mobile

A media query changes CSS rules at different screen sizes. This is often where mobile problems are fixed.

All devices 
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

@media (max-width: 760px) {
  .card-grid {
    grid-template-columns: 1fr;
  }
}
What this means: the cards are three columns on wider screens, but one column on smaller screens.

JavaScript: behavior and data

JavaScript controls what happens: opening panels, changing slides, filtering items, responding to clicks, reading data, updating text, moving maps, or switching views.

JavaScript concepts to recognize

You do not need to memorize all of JavaScript, but you should recognize the pieces that often appear in interactive elements, hosted embed customizations, and AI-assisted code.

Behavior

Variables store values so the code can use them later. Example: const currentSlide = 0;. You may edit values, labels, image paths, or settings stored in variables.

Functions are named blocks of behavior. Example: showSlide(2) might show the third slide. If something happens after a click, a function is probably involved.

Events are things the user or browser does: click, tap, scroll, resize, type, or load. Code often listens for events with addEventListener.

Conditionals make decisions. Example: if this panel is open, close it; otherwise, open it. Look for if, else, and comparison symbols like ===.

Loops repeat an action for many items. If a script creates cards, markers, timeline entries, or list items from data, it may use forEach or a for loop.

The DOM is the browser’s live version of the page. JavaScript can find HTML elements and change them. Look for document.querySelector, classList, textContent, and innerHTML.

JavaScript objects: editable data for visualizations

Many interactives use a JavaScript object or array of objects so you can add, remove, or edit content without touching the interaction logic.

Data you can edit 
const birds = [
  {
    name: "Bay-breasted Warbler",
    season: "Spring",
    image: "img/bay-breasted.jpg",
    alt: "Bay-breasted Warbler on a branch",
    description: "Chestnut throat, buff sides, and dark face."
  },
  {
    name: "Blackburnian Warbler",
    season: "Spring",
    image: "img/blackburnian.jpg",
    alt: "Blackburnian Warbler on a branch",
    description: "Bright orange throat and bold face pattern."
  }
];

How to read this

  • The square brackets mean this is an array: a list of items.
  • Each pair of curly braces is one object: one bird, one map stop, one timeline event, one card.
  • name, season, image, alt, description are keys. They should usually stay consistent.
  • The quoted text is the value. This is often the safest part to edit.
Student strategy: separate “data I can edit” from “code that makes the interaction work.” If using AI, ask it to label those sections clearly. Then add new objects by copying one whole object, including its commas and braces.

Common object editing mistakes

Most beginner JavaScript data errors come from small punctuation problems.

Debugging

Missing comma

Objects in an array usually need a comma between them. Missing commas can stop the whole script.

{ name: "A" },
{ name: "B" }

Unmatched braces

Every opening { or [ needs a closing } or ]. Copy the whole object, not only part of it.

{
  name: "A"
}

Inconsistent keys

If one object uses image, do not rename the next one photo unless the code was written to expect that.

image: "img/a.jpg"

Using AI carefully for code help

AI is useful for explaining unfamiliar code, finding small fixes, adding comments, and debugging. It should not replace testing, accessibility checks, or your own understanding of what the interaction does.

AI support

“Explain what this embed code does in plain language. Identify which parts control size, content, styling, and behavior.”

“Add START and END comments around the exact HTML block I should duplicate to add another item. Do not change the design.”

“Tell me which CSS selector controls this card spacing / iframe height / mobile layout. Give me the smallest change only.”

“Do not rewrite the full file. Only tell me the smallest HTML or CSS change needed to make this embed fit the story column.”

“This worked before I changed the iframe/style/data item. Check for the smallest likely error: missing comma, quote, bracket, brace, wrong file path, or fixed width.”
