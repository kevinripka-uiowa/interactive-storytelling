Coding basics for students using AI

You do not need to become a full-time programmer to make useful interactive elements. But you do need enough code literacy to understand what the AI produced, change simple details, avoid breaking the page, and explain what your interactive is doing.

Core idea: AI can generate code, but you remain responsible for the content, structure, usability, accessibility, attribution, and final testing.

What are you responsible for on a web page?

When you use AI-generated code, the main responsibility shifts from writing every line yourself to directing, editing, testing, and understanding the result.

Your responsibilities

These are the parts students should be able to evaluate even when the first draft of the code came from AI.

Code literacy
1

Structure

Does the page have a clear order? Are sections, headings, buttons, links, images, and labels used for the right jobs?

2

Content

Are the text, images, data, labels, sources, and examples accurate and appropriate for the story?

3

Appearance

Do the colors, type sizes, spacing, hierarchy, and layout make the element clear and readable?

4

Interaction

Does the user know what to click, tap, drag, scroll, or select? Does the interaction actually serve the story purpose?

5

Responsiveness

Does it work on a laptop and a phone? Does anything overflow, shrink too much, or require hover on mobile?

6

Accessibility

Can someone use it with keyboard controls? Are images described? Are buttons real buttons? Is color not the only cue?

What you need to know for vibe coding

Vibe coding works best when you can describe the intended behavior, identify which part of the file controls what, and ask for targeted changes.

AI workflow
  • Do not ask only for “make it better.” Ask for a specific change: “Make the cards 3 columns on desktop and 1 column on mobile.”
  • Keep the file organized. Ask AI to label major sections with comments so you can find them later.
  • Test after each change. Make one meaningful change, refresh the browser, and check desktop and mobile widths.
  • Know what layer you are editing. HTML changes structure/content. CSS changes appearance/layout. JavaScript changes behavior/data-driven interactions.

HTML: structure and meaning

HTML is the structure of the page. It tells the browser what each piece of content is: a heading, paragraph, image, link, button, section, list, table, or form control.

Simplified HTML syntax

Most HTML is made from elements. An element usually has an opening tag, content, and a closing tag.

Structure 
<section class="story-card">
  <h2>Migration route</h2>
  <p>Monarchs travel across multiple generations.</p>
  <button type="button">Show details</button>
</section>
  • <section> groups a meaningful part of the page.
  • class="story-card" gives CSS or JavaScript a name to target.
  • <h2> is a heading, not just big text.
  • <button> is for actions on the page. <a> is for links/navigation.

HTML terms to recognize

These are the terms you should be able to spot when AI gives you code.

Vocabulary

Elements are the building blocks of HTML. Examples include <h1>, <p>, <img>, <button>, and <section>.

Attributes add information to an element. Examples include class, id, src, alt, href, and aria-label.

A class can be reused on many elements. An ID should be unique on the page. CSS and JavaScript often use classes and IDs to target specific parts of the page.

Nesting means one element is inside another. If the opening and closing tags get mixed up, the layout or interaction can break.

Semantic HTML means using the element that matches the job: headings for structure, buttons for actions, links for navigation, lists for grouped items, and tables for actual table data.

Ask AI for a commented snippet you can duplicate

When your interactive has repeated elements, ask the AI to clearly mark the smallest chunk you can copy, paste, and edit.

Reusable chunks

For example, if you have a card-based interactive, ask for a comment like this:

<!-- START: Duplicate this whole article to add another bird card -->
<article class="species-card">
  <img src="img/warbler.jpg" alt="Bay-breasted Warbler on a branch">
  <h3>Bay-breasted Warbler</h3>
  <p>Look for the chestnut throat and buff sides in spring plumage.</p>
</article>
<!-- END: Duplicate this whole article to add another bird card -->
Prompt to use: “Add comments that show exactly which HTML block I should duplicate when I want to add another item. Also tell me which text, image path, alt text, and labels I should edit.”

CSS: appearance and layout

CSS controls how the page looks: color, typography, spacing, layout, borders, shadows, responsive behavior, and visual states like hover or focus.

Simplified CSS syntax

A CSS rule has a selector, curly braces, properties, and values.

Appearance 
.story-card {
  background: #fffdf7;
  color: #17211b;
  font-size: 18px;
  padding: 20px;
  border-radius: 16px;
}
  • .story-card is the selector. It targets HTML with class="story-card".
  • background, color, and font-size are properties.
  • #fffdf7, #17211b, and 18px are values.
  • Every property line should end with a semicolon.

Simple CSS fixes students should be able to make

These are common changes you can usually make without asking AI to rewrite the whole file.

Responsive CSS: desktop vs. mobile

A media query changes CSS rules at different screen sizes. This is often where mobile problems are fixed.

All devices 
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}

@media (max-width: 760px) {
  .card-grid {
    grid-template-columns: 1fr;
  }
}
What this means: the cards are three columns on wider screens, but one column on smaller screens.

JavaScript: behavior and data

JavaScript controls what happens: opening panels, changing slides, filtering items, responding to clicks, reading data, updating text, moving maps, or switching views.

JavaScript concepts to recognize

You do not need to memorize all of JavaScript, but you should recognize the pieces AI is likely to use in an interactive element.

Behavior

Variables store values so the code can use them later. Example: const currentSlide = 0;. You may edit values, labels, image paths, or settings stored in variables.

Functions are named blocks of behavior. Example: showSlide(2) might show the third slide. If something happens after a click, a function is probably involved.

Events are things the user or browser does: click, tap, scroll, resize, type, or load. Code often listens for events with addEventListener.

Conditionals make decisions. Example: if this panel is open, close it; otherwise, open it. Look for if, else, and comparison symbols like ===.

Loops repeat an action for many items. If AI creates cards, markers, timeline entries, or list items from data, it may use forEach or a for loop.

The DOM is the browser’s live version of the page. JavaScript can find HTML elements and change them. Look for document.querySelector, classList, textContent, and innerHTML.

JavaScript objects: editable data for visualizations

AI may create a JavaScript object or array of objects so you can add, remove, or edit items without touching the interaction logic.

Data you can edit 
const birds = [
  {
    name: "Bay-breasted Warbler",
    season: "Spring",
    image: "img/bay-breasted.jpg",
    alt: "Bay-breasted Warbler on a branch",
    description: "Chestnut throat, buff sides, and dark face."
  },
  {
    name: "Blackburnian Warbler",
    season: "Spring",
    image: "img/blackburnian.jpg",
    alt: "Blackburnian Warbler on a branch",
    description: "Bright orange throat and bold face pattern."
  }
];

How to read this

  • The square brackets mean this is an array: a list of items.
  • Each pair of curly braces is one object: one bird, one map stop, one timeline event, one card.
  • name, season, image, alt, description are keys. They should usually stay consistent.
  • The quoted text is the value. This is often the safest part to edit.
Student strategy: Ask AI to separate “data I can edit” from “code that makes the interaction work.” Then add new objects by copying one whole object, including its commas and braces.

Common object editing mistakes

Most beginner JavaScript data errors come from small punctuation problems.

Debugging

Missing comma

Objects in an array usually need a comma between them. Missing commas can stop the whole script.

{ name: "A" },
{ name: "B" }

Unmatched braces

Every opening { or [ needs a closing } or ]. Copy the whole object, not only part of it.

{
  name: "A"
}

Inconsistent keys

If one object uses image, do not rename the next one photo unless the code was written to expect that.

image: "img/a.jpg"

Useful AI prompts for coding work

These prompts help keep AI-generated code usable for students who need to edit and maintain it.

Prompting

“Put all the content I am likely to edit in one clearly labeled section near the top. Comment each field so I know what to change.”

“Add START and END comments around the exact HTML block I should duplicate to add another item.”

“Add comments in the CSS showing where to change colors, type sizes, spacing, and mobile layout.”

“Do not rewrite the full file. Only tell me the smallest CSS change needed to make the cards two columns instead of three.”

“This worked before I added a new item. Check the JavaScript object punctuation and tell me exactly where the missing comma, quote, bracket, or brace is.”
