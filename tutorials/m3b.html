Tutorial M3 - B

Build an Exploratory Data Visualization in Flourish

In this tutorial, you will use Flourish’s Data Explorer template to create a searchable and filterable visualization of the top 100 Major League Baseball players by career wins above replacement, or WAR.

Exploration still needs a purpose. Do not present a data dump and expect the reader to find the story. Frame the visualization around a question, then provide controls that help the reader investigate it.

What you will build

An interactive player explorer in which readers can search for a player, filter hitters and pitchers, and order the display by different statistics.

What you will submit

The public URL to the published Tilda page containing your embedded Flourish visualization.

Video walkthrough

Video update: The video does not include the final section where you set the Flourish visualization height. Follow the written instructions at the end of this tutorial to add the 800-pixel height settings.

Purpose and tool choice

Begin with the interaction you want, then select the builder that gets closest to it.

Define the exploration

The data includes the actual top 100 players and career WAR values, but the remaining statistics were generated only for this tutorial.

Purpose
  • The reader should be able to search for an individual player.
  • The reader should be able to compare hitters and pitchers.
  • The reader should be able to reorder the players by different statistics and consider how those statistics relate to WAR.
  • The visualization should support an explanatory story rather than function as an unframed database.
Data warning: Only the player list and career WAR are intended as real data. Treat the other values as fabricated tutorial data and label them clearly.

Compare available builder templates

Flourish offers many more templates than Datawrapper, but more options do not guarantee the exact interaction you need.

Tool choice
  1. Review Flourish’s available templates and filters for visualization type and purpose.
  2. Consider a bar chart, searchable table, or table of charts.
  3. Reject templates that allow only one bar or line measure when the exploration requires several statistics.
  4. Open the Data Explorer template because it supports search, filters, visual encodings, and multiple measures.
View the Datawrapper version discussed in the video.
Builders are constraints: Test a likely template quickly. Within a few minutes, you should know whether it can support the purpose of the visualization.

Section 1: Import the data

Flourish begins with sample data so you can inspect the template before replacing it with your own.

Create the visualization and upload the CSV

Use the sample visualization to understand the template, then replace the dummy data.

Setup
  1. Log in to Flourish and choose New visualization.
  2. Search for and select the Data Explorer template.
  3. Give the visualization a useful project name, such as WAR Explorer.
  4. Open the Data tab.
  5. Download fake-war.csv from ICON and upload it to replace the sample data.
  6. Confirm that the first row has become the set of column names.

Section 2: Assign the data columns

Tell Flourish which columns contain names, categories, numbers, and filters.

Map columns to the Data Explorer

The column selectors may not look interactive, but clicking them allows you to enter column letters and ranges.

Data mapping
  1. Use the Player column as the item name or label.
  2. Assign Position as the categorical column.
  3. Assign the statistical fields as numeric columns. Include the numeric ranges on both sides of the Position column.
  4. Do not treat Rank as the primary label. The player’s name should remain the visible identifier.
  5. Preview the visualization and confirm that all players appear.
Column letters depend on the CSV: Follow the letters shown in your Flourish data table. The purpose is to include Player as the name, Position as the category, and the statistical measures as numeric data.

Section 3: Frame the exploration

Use the header to explain what readers should investigate and how to use the controls.

Add a headline and directional subtitle

The surrounding article should explain WAR in depth. The visualization header should orient readers and cue interaction.

Headline
  1. Open the Header settings.
  2. Add a clear title, such as Wins Above Replacement Explorer.
  3. Add a subtitle that tells readers what to do, such as Use the controls to compare how the top 100 baseball players accumulated career WAR.
  4. Keep the framing tied to a question. For example: What statistics distinguish the players with the highest WAR?
Attendant text matters: A searchable graphic still needs a frame. The reader should know why exploration is worthwhile before interacting.

Section 4: Encode WAR visually

Use position, size, and color to make the central measure visible before the reader touches a control.

Use size and color to emphasize WAR

WAR is the organizing measure, so it should control the most immediate visual attributes.

Visual encoding
  1. In the visualization settings, set Size by to WAR.
  2. Set Color by to WAR.
  3. Use a sequential linear color scale because WAR progresses from lower to higher values.
  4. Select a readable single-hue palette, such as the green palette used in the video.
  5. Adjust the maximum point radius only when the largest circles overwhelm the display.
Redundant encoding can help: Size and color both communicate WAR. Readers can identify the highest-WAR players more quickly because two preattentive attributes reinforce the same measure.

Section 5: Configure and label the controls

Keep only the controls that support the intended exploration, then rewrite their labels and data names for readers.

Simplify the available controls

Do not expose settings that should remain fixed or that add no useful agency.

Interaction
  1. Open the Controls settings.
  2. Keep the search box available so readers can locate a player.
  3. Use the main position control to let readers order the visualization by a selected statistic.
  4. Turn off a second position control, map-shape controls, and other options that do not support this project.
  5. Set the filter field to Position so readers can choose all players, hitters, or pitchers.
  6. Set color and size to WAR. Initially hide those controls so users do not change the central encoding.
  7. Turn off aggregation because the visualization is showing individual players rather than grouped summaries.

Improve the interface microcopy

Generic builder labels and raw spreadsheet headers may not tell readers what the controls do.

Microcopy
  1. Change the label Position to Order by stat.
  2. Change the filter label to Filter by position.
  3. Return to the Data tab and edit the visible column names that appear in the menus.
  4. Replace machine-style headers such as offensive_war and seasons_played with reader-facing labels such as Offensive WAR and Seasons Played.
  5. Capitalize abbreviations and baseball statistics consistently.
  6. Publish the changes so the corrected names appear in the embedded controls.
You do not need to re-upload the spreadsheet: Flourish allows you to edit the displayed column headers directly in its Data tab.

Section 6: Refine labels, popups, and source information

Review the remaining settings, but change only those that improve understanding.

Finish the presentation details

The template includes many settings. Treat them as possibilities, not requirements.

Refinement

A. Item labels and popups

  • Keep player names as the item labels.
  • Avoid switching labels to Rank unless rank is central to the exploration.
  • Leave popup content on automatic, or customize it with column names inside double curly brackets when a deliberate popup is needed.

B. Search

  • Decide whether the search field should always remain expanded.
  • Test a known player, such as Babe Ruth, to confirm that search highlights the correct item.

C. Footer and source

  • Add a source label that makes the tutorial data unmistakable.
  • Use wording such as AI-generated fake data for tutorial use.
  • Do not attach a source URL when there is no legitimate source page for the fabricated statistics.

Section 7: Accessibility and all devices

Describe the visualization for screen readers and test how the explorer behaves at different widths.

Add accessibility information

The description should explain both the content and the available interaction.

Accessibility
  1. Open the Accessibility settings.
  2. Add a screen-reader description, such as: An explorable plot of the top 100 MLB players by career WAR. Users can order players by statistics, search for a player, or filter hitters and pitchers.
  3. Add a concise screen-reader label, such as Wins Above Replacement Explorer.
  4. Confirm that the title, instructions, controls, and source remain understandable without relying only on color.

Test responsive behavior

The editor preview may make the mobile version look too small, so also test the visualization at a wider preview size and on the published page.

All devices
  1. Use Flourish’s preview controls to inspect the visualization at several widths.
  2. Increase the preview width to confirm that the visualization expands responsively.
  3. Check whether the controls, labels, and plotted items remain usable on a narrow screen.
  4. Do not assume the editor preview exactly matches the final embedded page.

Section 8: Publish and embed in Tilda

Publish the visualization, copy Flourish’s embed code, and place it inside a Custom HTML block.

Publish from Flourish

Flourish’s embed uses JavaScript rather than a simple fixed-height iframe, which can make responsive height easier to manage.

Publish
  1. Choose Export & publish.
  2. Publish the visualization.
  3. Copy the website embed code.
  4. Open the assigned Module 3 tutorial page in Tilda.
  5. Add a Custom HTML block and paste the Flourish embed code into its Content panel.
  6. Save, publish the Tilda page, and open the public page.

Section 9: Diagnose the embed, fix it, and republish

The first published result exposes two builder limitations. Keep this troubleshooting step because testing the real embed is part of the production process.

Restore the fixed WAR encodings

On the published Tilda page, the visualization may not initially preserve the selected WAR size and color settings.

Troubleshooting
  1. Return to Flourish and reopen Controls.
  2. Turn the Size and Color controls back on.
  3. Limit each control so that WAR is the only available option.
  4. Republish the Flourish visualization.
  5. Refresh the Tilda page and confirm that the updated embed loads from Flourish.
Imperfect result: Readers may still need to select WAR in the visible controls. The builder cannot fully deliver the intended default behavior, but the tutorial keeps the result so you can see the limitation rather than hide it.

Set the embedded visualization’s width and height

The first embed may become too large or too short. Wrap the Flourish code in a centered container and set the height in both the wrapper and the Flourish embed.

Layout fix
  1. Return to the Custom HTML block in Tilda.
  2. Wrap the Flourish embed in a <div> with a maximum width of 800 pixels, automatic horizontal margins, and a height of 800 pixels.
  3. Add data-height="800px" to the Flourish embed div.
  4. Keep the vertical margin at 3rem to create space above and below the visualization.
  5. Save the block and publish the Tilda page again.
  6. Open the public page and confirm that the visualization is centered, no wider than 800 pixels, and tall enough to use comfortably.
<div style="max-width:800px;margin:3rem auto;height:800px;">
  <div class="flourish-embed flourish-data-explorer" data-height="800px" data-src="visualisation/29766660">
    <script src="https://public.flourish.studio/resources/embed.js"></script>
    <noscript>
      <img src="https://public.flourish.studio/visualisation/29766660/thumbnail" width="100%" alt="data-explorer visualization" />
    </noscript>
  </div>
</div>
Set the height twice: The wrapper reserves 800 pixels of space on the page, while data-height="800px" tells Flourish how tall to render the visualization.
Republishing matters: Updating Flourish refreshes the hosted visualization. Updating this wrapper requires saving and republishing the Tilda page.

Submission

Submit the published page after testing the real embed.

Upload the public URL to your published Tilda page. Do not submit the Flourish editor URL or the Tilda editor URL.
