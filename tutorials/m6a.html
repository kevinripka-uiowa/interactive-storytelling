Challenge · 360 Tour

Build a Two-Scene 360 Tour

Use the supplied template to create a short spatial story from two equirectangular 360 images. You will decide what deserves annotation, place hotspots where they make visual sense, and connect the scenes into one tour.

This is a challenge, not a click-by-click tutorial. Use the template README as your technical reference. Your job is to understand the configuration well enough to replace the sample content and make intentional editorial choices.

What you will build

A two-scene 360 tour with embedded media, descriptive annotations, teleportation between scenes, and a centered presentation in Tilda.

What this challenge tests

Your ability to read documentation, edit a configuration, place interface elements spatially, troubleshoot code, and integrate a custom interactive into a page builder.

Challenge requirements

Your finished tour must satisfy every requirement below. The hotspots should support the content of your images rather than functioning as arbitrary demonstrations.

Required features

Checklist

Scene 1

  • Replace the first sample panorama with your own 360 image.
  • Add one embedded-media hotspot with a written description.
  • Add one description-only hotspot.
  • Move both hotspots to locations that make sense within your image.

Scene 2

  • Replace the second sample panorama with a different 360 image.
  • Add one teleport hotspot that returns to Scene 1.
  • Add one image hotspot with a written description.
  • Move both hotspots to meaningful locations within the image.

Template and reference

The repository contains the working template, its file structure, examples, and the complete configuration reference.

Use the repository documentation

Reference
  • 360 Hotspots Template on GitHub

Keep the README open while working. Use it to check scene properties, hotspot types, embedded-media code, descriptions, teleport destinations, scene thumbnails, and accessibility fields.

Do not depend on the sample coordinates

The template coordinates match the sample images. Once you replace those images, the sample hotspots will point to unrelated parts of your scenes.

Section 1: Download and open the template

Begin with the complete project so the panorama viewer, hotspot behavior, accessibility features, and styles remain intact.

Prepare a local working copy

Start
  1. Open the GitHub repository.
  2. Choose Code → Download ZIP.
  3. Unzip the project and rename the folder for your tour.
  4. Open the complete folder in Visual Studio Code.
  5. Use Live Server to preview index.html.
Keep the project together

Do not open or move only index.html. The image paths depend on the project folder and its supporting files.

Section 2: Replace both 360 scenes

Choose two equirectangular images that belong together as a small tour, comparison, sequence, or exploration.

Update the scene images and information

Scenes
  1. Place both panorama files inside the project’s image folder.
  2. Find the P360_SCENES configuration in index.html.
  3. Replace the sample image path in each scene.
  4. Give each scene a useful title and a meaningful text description.
  5. Update thumbnail images if you keep the optional scene-thumbnail navigation.
Use true 360 images

Each panorama should use a 2:1 equirectangular projection. A normal wide photograph will stretch and distort inside the viewer. You may find openly shared examples in the Equirectangular group pool on Flickr. Check the license on each individual image and provide attribution when required.

Section 3: Build the first scene

The first panorama must combine interpretation, media, and navigation.

Have two purposeful hotspots

Scene 1

Embedded-media hotspot

Choose a visible feature that benefits from audio, video, a map, a model, or another hosted media player. Use the service’s complete embed code in the template’s embed field. Include a written description that explains what the media adds and how it relates to the visible feature.

Description hotspot

Add explanatory text about a visible feature, place, object, person, or environmental detail. The description may include simple HTML such as paragraphs, links, emphasis, or a short list.

Section 4: Build the second scene

The second panorama must include a way back to the first scene and one image-based annotation.

Have a teleport and an image hotspot

Scene 2

Teleport hotspot

Add a teleport hotspot that returns to Scene 1. Place it where the transition makes spatial or narrative sense rather than in an arbitrary open area.

Image hotspot

Add an image that helps viewers understand something visible in the panorama. The image hotspot must also include a written description that explains the image and its relationship to the scene.

  • Write clear hotspot labels and meaningful descriptions.
  • Include alt text for the image.
  • Include source information or attribution for media you did not create.

Section 5: Position and test every hotspot

Hotspot coordinates are part of the storytelling. They should direct attention to the correct feature without obscuring it.

Find meaningful pitch and yaw coordinates

Placement
  1. Open the tour with Live Server.
  2. Rotate the panorama until the intended feature is centered.
  3. Use the coordinate information provided by the template.
  4. Transfer the pitch and yaw values into the correct hotspot object.
  5. Reload and confirm that the hotspot appears beside the intended feature.
  6. Repeat for every hotspot in both scenes.
Do not leave the sample hotspots in place

A technically working hotspot is not enough. Its position must communicate a clear relationship to something viewers can see in the panorama.

Section 6: Move the finished tour into Tilda

After the local version works, place the namespaced template code inside a Tilda HTML block and constrain its width.

Paste and center the tour

Tilda
  1. Add a T123 Embed HTML Code block to your Tilda page.
  2. Copy the template code from index.html into the block.
  3. Find the CSS rule for #p360-root.
  4. Add a maximum width of 800px and center the tour with automatic left and right margins.
  5. Save and publish the page. Tilda does not fully run custom code inside the editor preview.
#p360-root {
  width: 100%;
  max-width: 800px;
  margin: 0 auto;
}
Recheck image paths after moving to Tilda

Local relative paths such as images/scene-one.jpg will not work unless those images are also hosted online. Use public image URLs or another hosting method supported by your project.

Final check

Test the published version as a viewer rather than only checking whether the code runs.

Confirm the complete experience

Quality control
  • Both panoramas load and rotate correctly.
  • The first scene includes embedded media with a description, a description-only hotspot, and the existing teleportation hotspot.
  • The second scene includes a return teleport and an image hotspot with a description.
  • Every hotspot points to the intended feature.
  • The teleport opens the correct destination scene.
  • Embedded media works on the published Tilda page.
  • The tour is centered and no wider than 800 pixels.
  • The scene descriptions and hotspot labels make sense in the text description view.
  • The page works with keyboard navigation and at a narrow mobile width.
  • All outside media is credited and permitted for use.
