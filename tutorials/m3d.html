Tutorial M3 - D

Build an Interactive SVG Diagram

In this tutorial, you will turn a labeled bird-wing SVG into an interactive diagram. Hovering or clicking a bone will reveal a tooltip and reduce the opacity of the surrounding parts.

The main lesson is not simply how to make hotspots. You will learn how SVG elements, groups, IDs, JavaScript objects, and interaction code connect. That structure can also be used for maps, diagrams, illustrations, and other interactive graphics.

What you will build

An interactive bird-wing diagram with hover and click states, focus through opacity, and tooltips containing a title and description.

Video walkthrough

Before you start

Download the Module 3D tutorial assets from ICON before opening Illustrator or VS Code.

Gather the files

The supplied files keep the tutorial focused on SVG structure and interaction rather than drawing the wing from scratch.

Setup
  • wing.svg
  • The wing-bone JSON or JavaScript data file
  • The supplied CSS, JavaScript, tooltip HTML, and prompt files
  • Adobe Illustrator
  • VS Code with Live Server
  • Access to ChatGPT or another coding assistant
Alternative technique: Raster images can also have interactive regions through HTML image maps. This tutorial uses SVG because its individual shapes and groups can be selected and styled directly with CSS and JavaScript.

Section 1: Understand SVG structure

An SVG is an image format, but its contents are also structured markup that behaves much like HTML.

Identify the elements you can target

Interactive SVGs work because individual shapes can carry IDs, classes, and other attributes.

SVG concepts
  • <svg>: the outer element that contains the full graphic.
  • Shape elements: paths, rectangles, circles, polygons, and other drawing instructions.
  • <g> groups: collections of shapes that can be treated as one meaningful part.
  • IDs and classes: labels that let CSS and JavaScript find a specific group or set of groups.
Why groups matter: A single anatomical part may contain several paths. Group those paths so one interaction can control the entire part.

Section 2: Organize the SVG in Illustrator

Prepare the artwork so each interactive region is represented by a clearly named top-level group.

Check and name the wing-bone groups

The layer names created in Illustrator will become IDs in the exported SVG.

Illustrator
  1. Open wing.svg in Illustrator.
  2. Open the Layers panel and inspect the named groups, including humerus, ulna, radius, carpometacarpus, digits, and alula.
  3. Expand several groups to confirm that they contain the paths belonging to that anatomical part.
  4. Find the two shapes that form the alula.
  5. Select both shapes, then choose Object > Group or press Command-G.
  6. Rename the new group alula.
  7. Leave unrelated artwork in a separate top-level group named other.
Use exact, consistent names: The group IDs must later match the keys in the JavaScript data object. Avoid spaces and inconsistent spelling.

Section 3: Export and clean the SVG

Export SVG code, then remove Illustrator’s unnecessary markup before placing it in the web page.

Produce usable inline SVG code

Inline SVG exposes the internal groups to CSS and JavaScript. An SVG loaded with an image tag does not provide the same direct access.

Optimization
  1. Choose File > Save As and save a separate SVG so the original asset remains unchanged.
  2. In Illustrator’s SVG options, open or copy the generated SVG code.
  3. Paste the code into an SVG cleaning or optimization tool.
  4. Run the cleaner and download the optimized SVG.
  5. Open the cleaned file in a text editor.
  6. Inspect the markup and confirm that the expected top-level group IDs remain intact.
  7. Watch for anonymous path IDs or names changed during export. Correct problems before building the interaction.
Cleaning is not merely cosmetic: Illustrator often exports metadata and verbose code. Cleaner markup is easier to inspect, debug, and paste into a builder.

Section 4: Set up the HTML project

Build and test the interactive locally before moving it into Tilda.

Add the inline SVG to a page

A simple local project makes it easier to inspect code and test changes immediately.

HTML
  1. Create a new project folder.
  2. Open the folder in VS Code.
  3. Create index.html.
  4. Add an HTML5 page wrapper.
  5. Copy the cleaned SVG markup and paste it inside the body.
  6. Start Live Server to preview the page.
  7. Wrap the SVG in a container such as <div style="max-width:600px;margin:0 auto;">.
  8. Place the closing </div> after the closing </svg> tag.
Control the container, not a fixed SVG width: A maximum-width wrapper allows the SVG to shrink responsively on smaller screens.

Section 5: Connect SVG IDs to data

Use a JavaScript object to store the title and description associated with each wing-bone group.

Add the wing-bone object

The matching names form the bridge between the artwork and the tooltip content.

JavaScript data
  1. Add a <script> element near the end of the body.
  2. Open the supplied JSON or JavaScript data file.
  3. Paste the wingBones constant inside the script element.
  4. Inspect the object. Each top-level key represents one bone.
  5. Confirm that every bone object contains a title and description.
  6. Compare the object keys with the SVG group IDs. They must match exactly.
  7. Confirm that other is not included in the data because it will not receive a tooltip.
Understand the hierarchy: The SVG contains top-level groups that may contain nested groups and paths. The interaction should target only direct child groups of the SVG, not every nested group.

Section 6: Write the AI prompt

Describe the existing structure and the desired behavior precisely enough that the generated code can work with your file.

Prompt from an understanding of the document

AI is useful for producing interaction code, but only after you understand what must be selected and how the data is organized.

AI-assisted coding

Include these requirements

  • The uploaded HTML contains an inline SVG and a JavaScript object.
  • Add hover and click events to each top-level SVG group except the group with the ID other.
  • Use the group ID to retrieve the matching title and description from wingBones.
  • Show a tooltip that follows the pointer.
  • Place the tooltip to the right of the pointer over the left half of the SVG and to the left over the right half.
  • When a group is hovered or selected, reduce every other top-level group, including other, to opacity: 0.3.
  • Support click interaction so the diagram remains usable on touch devices.
Do not ask AI to infer everything: Naming the exact selector level, excluded group, data source, tooltip content, positioning rule, and mobile interaction produces a much more reliable result.

Section 7: Add the generated code

Separate the generated CSS and JavaScript, then place each piece in the correct location.

Integrate the response carefully

Generated files still need to be inspected rather than pasted blindly.

Integration
  1. Upload your current HTML file with the prompt.
  2. Download or inspect the revised file produced by the AI tool.
  3. Find the generated tooltip and interaction CSS.
  4. Copy that CSS into a <style> element inside the body or into the supplied CSS area.
  5. Find the generated JavaScript.
  6. Copy only the JavaScript code, not another pair of script tags.
  7. Paste it inside your existing <script> element after the wingBones object.
  8. Save and test the page.
Avoid duplicate wrappers: If your page already has <style> or <script> tags, paste the code inside them rather than nesting another set of tags.

Section 8: Fix the missing tooltip

The first test may show the focus effect without displaying the tooltip. Keep this debugging step rather than hiding it.

Add the tooltip element the script expects

CSS and JavaScript cannot display a tooltip element that does not exist in the page.

Troubleshooting
  1. Test the page and confirm whether the hovered group remains fully opaque while other groups fade.
  2. If no tooltip appears, inspect the AI-generated file.
  3. Search the file for tooltip.
  4. Locate the small HTML element used as the tooltip container.
  5. Copy that element into your project.
  6. Place it inside the SVG wrapper, after the SVG markup.
  7. Save and test again.
Read the whole generated solution: The interaction depended on three parts: CSS, JavaScript, and a tooltip element in the HTML. Missing any one of them produces an incomplete result.

Section 9: Test hover, click, and touch behavior

Hover is useful on desktop, but click support is necessary because touchscreens do not have a persistent hover state.

Check the complete interaction

Test both the visual hierarchy and the tooltip behavior at several viewport sizes.

All devices
  1. Hover over each labeled bone on desktop.
  2. Confirm that its tooltip displays the correct title and description.
  3. Move across both halves of the SVG and confirm that the tooltip changes sides to avoid the pointer and page edge.
  4. Confirm that all non-active top-level groups fade to 0.3 opacity.
  5. Click a bone and confirm that the active state can remain visible.
  6. Resize the browser or use device emulation.
  7. Tap the diagram and confirm that the tooltip appears on a touch-sized layout.
Mobile may need more art direction: A pointer-following tooltip can be awkward on a small screen. For a polished project, consider a fixed information panel or bottom sheet on mobile.

Section 10: Publish in Tilda

Move only the contents of the body into a Custom HTML block.

Add the interactive to the tutorial page

The local HTML skeleton is useful for testing, but Tilda already supplies the document structure.

Publish
  1. Log in to Tilda and open your Module Tutorials page.
  2. Add or open a Custom HTML block.
  3. In VS Code, select everything inside the opening and closing <body> tags.
  4. Do not copy the doctype, <html>, <head>, or body tags themselves.
  5. Paste the body content into the Custom HTML block.
  6. Save and close the block.
  7. Publish the page.
  8. Open the public page and test the interaction again.
  9. Add a headline and brief explanatory text so viewers understand that the graphic identifies parts of a bird wing.
Context still matters: An interactive diagram should not appear as an unexplained object. Attendant text should tell viewers what they are seeing and what they can do.

Production checks

Review the interactive through the course’s production concerns before submitting it.

Apply the 5 A’s

The SVG technique gives you considerable control, which also gives you responsibility for the result.

5 A’s
  • Appearance: Provide a clear headline, readable tooltip, and obvious focus state.
  • Asset optimization: Use cleaned SVG markup and remove unnecessary Illustrator data.
  • All Devices: Support click or tap in addition to hover and test the tooltip on small screens.
  • Accessibility: Do not rely only on color or opacity. Ensure interactive groups can eventually receive keyboard focus and that the same information is available in text.
  • Attribution: Credit the illustration and the source of the anatomical information when required.
Accessibility limitation: The video build emphasizes pointer and touch interaction. A fully finished version should also add keyboard operation, visible focus styles, and appropriate labels for each interactive group.
