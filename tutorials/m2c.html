Build Flip Cards in a Tilda Custom HTML Block

In this tutorial, you will use code in a Tilda custom HTML block to build a set of flippable cards. The goal is not to become a full-time programmer. The goal is to practice code literacy: describing what you need, using AI or reference code carefully, editing repeated content, replacing image URLs, and testing the final result.

Custom code gives more control and more responsibility. A custom HTML block can create interactions that a native block may not provide, but you are responsible for the code, layout, accessibility, assets, and final testing.

What you will build

A responsive flip-card interactive about bird bill types, pasted into Tilda as one self-contained custom HTML snippet with embedded CSS and JavaScript.

What you will submit

The public URL to your published Tilda page, not the Tilda editor URL.

Build the custom HTML flip-card interactive

This tutorial uses a custom HTML block because the interaction needs more control than a native block provides. The task is to direct the code, test it, and make small edits responsibly.

Section 1: Plan the interaction

Purpose

Start by describing the interaction in plain language before thinking about the code.

  1. Decide that the pattern is a flip-card set.
  2. Define the user action: the viewer clicks or taps a card to flip it.
  3. Define the reveal: the back of the card shows a short explanation and examples.
  4. Recognize the limitation: flip cards can become gimmicky if the front and back do not have a clear relationship.
  5. Use the pattern only because it gives the viewer a useful reveal, not because the animation is fun.
Flip cards can be hard to use

The front should create a clear reason to flip the card. The back should reward the click with useful information. If the viewer has to flip everything just to understand the basics, the pattern may be weak.

Section 2: Write a detailed prompt

Prompting

Do not ask only for “make flip cards.” A useful prompt describes the interaction, host platform, content, layout, accessibility, and output format.

  1. Open a blank text document or note.
  2. Start with the interaction: “I want to create a flippable cards interactive where a user clicks to flip a card to reveal information on the back.”
  3. Add the host context: the code will be pasted into a Tilda custom HTML block.
  4. Ask for a self-contained HTML snippet with embedded CSS and JavaScript.
  5. Tell the AI not to include a full HTML document unless necessary.
  6. Require scoped CSS so the snippet does not interfere with the rest of the Tilda page.
  7. Tell the AI not to use external libraries unless there is a strong reason.
I want to create a flippable cards interactive where a user clicks to flip a card to reveal information on the back.

I will paste this into a custom HTML block in Tilda. Give me a self-contained HTML snippet with embedded CSS and JavaScript. Do not include a full HTML document unless necessary. Scope all CSS to this interactive so it does not affect the rest of the page. Do not use external libraries unless there is a strong reason.

Section 3: Set the production context

Tilda

The code should be written for the place it will actually live. In this case, it needs to fit inside Tilda’s content area.

  1. Tell the AI the interactive should be centered horizontally on the page.
  2. Tell it to fit inside Tilda’s grid: about 1160 pixels of content with margins on each side.
  3. Ask for three cards per row on desktop, two on tablet, and one on mobile.
  4. Require the snippet to be easy to paste into one custom HTML block.
I want this entire thing centered horizontally on the page. It should fit inside Tilda's grid, which is about 1160px of content with margins left and right.

Use three cards per row on desktop, two on tablet, and one on mobile.
Production context matters

A custom code block does not exist in isolation. It sits inside a builder page, so width, spacing, fonts, and responsive behavior should match the page environment.

Section 4: Describe the content and layout

Content

Give the AI enough content direction so it creates the right structure instead of guessing.

  1. On the front of each card, ask for a square image and the title of the bird bill type.
  2. Place the title over the image at the bottom, not underneath the image.
  3. On the back, ask for a short description and a separate section for the types of birds that have that bill type.
  4. Ask for a small attribution line.
  5. Tell the AI that the back text should center vertically.
  6. Paste the sample content from the asset file into the prompt.
On the front of the cards I want a square image and a title of the type of bird bill.

On the back I want a sentence of description and another section that tells what types of birds have this bill type. I also want a small attribution.

I want the text on the front to be over the image, not under it, and placed at the bottom of the image. Text on the back should center vertically.

Section 5: Add production requirements

5 A’s

Use the prompt to require the production features you would otherwise have to fix later.

  1. Appearance: ask for a clear title and short instructional paragraph above the cards.
  2. Asset optimization: use replaceable image paths or a temporary placeholder image URL; do not use Base64 images.
  3. All devices: require a responsive layout and touch-friendly controls.
  4. Accessibility: require semantic HTML, buttons for actions, keyboard access, visible focus states, and alt text fields.
  5. Attribution: include a small attribution area for each card or image.
Add a clear title and short instructional paragraph above the cards.

Use replaceable image URLs. Do not use Base64 images.

Make the interaction keyboard accessible. Use semantic HTML and real buttons for actions. Include visible focus states and alt text areas for images.

Include small attribution text for each card.

Section 6: Generate one code snippet

AI assistance

After the prompt is complete, paste it into the AI tool and ask for one usable snippet.

  1. Paste the complete prompt into the AI assistant.
  2. If the response splits the code into separate pieces, ask it to combine everything into one code snippet.
  3. Copy the full snippet only after you confirm that it includes HTML, CSS, and JavaScript in one block.
  4. Do not copy extra explanation into Tilda; copy only the code.
Make this one code snippet I can cut and paste.
AI can structure code strangely

If the first output is broken, split apart, or missing a requirement, ask for a targeted revision. Do not start over unless the structure is unusable.

Section 7: Paste the code into Tilda

Custom HTML
  1. Open your Tilda tutorial page.
  2. Add a new block where the flip-card interactive should appear.
  3. Choose the Custom HTML block from the Other block category.
  4. Open the block Content panel.
  5. Paste the single code snippet into the custom HTML field.
  6. Save and close the block.
  7. Publish the page. Custom HTML often needs the published page to test accurately.
Preview is not enough

The editor preview may not fully run custom HTML, CSS, JavaScript, or iframe content. Publish to a practice page and test the real public page.

Section 8: Publish and inspect the first version

Testing
  1. Open the published page.
  2. Click or tap each card to confirm it flips.
  3. Check whether the layout matches the requested desktop, tablet, and mobile columns.
  4. Check whether the visual style fits the rest of the Tilda page.
  5. Check whether the card fronts, backs, images, and text are readable.
  6. Write down the changes needed before asking AI to revise anything.
Own the result

AI may take liberties with fonts, colors, wording, or structure. You are still responsible for whether the final interactive fits the page and the assignment.

Section 9: Use Tilda-hosted image URLs

Assets

Images used in custom HTML need public URLs. One practical Tilda workflow is to upload an image into a normal image block, publish, then copy the optimized image URL.

  1. Add a temporary image block in Tilda.
  2. Upload the image you want to use in one of the flip cards.
  3. Use Tilda’s image settings to display it near the size needed for the card.
  4. Publish the page.
  5. Open the published page and open the image in a new tab.
  6. Copy the optimized image URL, often served as a web-friendly format such as WebP.
  7. Return to the custom HTML block and replace the placeholder image URL with the copied Tilda image URL.
  8. Delete the temporary image block when you no longer need it.
File size is different from display size

Display size controls how large the image appears on the page. File size controls how heavy the download is. Use reasonable image files and let Tilda’s optimization help, but do not upload huge originals if you do not need them.

Section 10: Edit the HTML content

Code literacy

After the first version works, edit the repeated card blocks instead of asking AI to regenerate everything.

  1. Open the custom HTML block Content panel.
  2. Find the repeated card item you want to change.
  3. Replace the card title text.
  4. Replace the image URL.
  5. Update the image alt text.
  6. Replace the description and bird-type examples on the back.
  7. Update the attribution text.
  8. Save, publish, and check the change.
<img src="REPLACE-WITH-TILDA-IMAGE-URL" alt="Great Blue Heron bill close up">
Edit the content, not the logic

For repeated card patterns, the safest edits are usually text, image paths, alt text, labels, and attribution. Be careful not to delete closing tags, braces, or wrapper elements.

Section 11: Duplicate a card

Repeatable pattern
  1. Find the comment that marks the start of one complete card item.
  2. Select the entire repeated card block, including the start and end comments if present.
  3. Copy and paste the full block before the closing wrapper of the card grid.
  4. Change the comment or label so it is clear this is the new item.
  5. Replace the title, image, alt text, description, birds-with-this-bill text, and attribution.
  6. Publish and confirm that the new card appears in the grid without breaking the layout.
<!-- START: Duplicate this whole card to add another item -->
<article class="flip-card">
  ...
</article>
<!-- END: Duplicate this whole card to add another item -->
Do not break the wrapper

The grid container wraps all the cards. If you paste a new card outside that wrapper, the layout may break. If you delete the wrapper’s closing tag, the whole interactive may fail.

Section 12: Ask AI to revise your changed code

Revision workflow

If you have already edited the code, make the AI start from your current version, not from the original draft.

  1. Open the custom HTML block and copy your current full code.
  2. Tell the AI that you have changed the code and it should use your pasted version as the starting point.
  3. Ask for specific changes rather than a broad rewrite.
  4. For this tutorial, ask for individual background colors on each card using CSS variables.
  5. Ask for sans-serif typography with TildaSans as the preferred font.
  6. Paste the changed code after the instruction.
Revise this code, but I have changed it, so start with my changed code that I will paste.

I want to add individual background colors to each card. Please use CSS variables.

I also want the typography to be sans-serif fonts, using TildaSans as the preferred sans-serif.

Do not lose your edits

If you ask AI to revise from memory or from an earlier version, it may remove the images, content, or extra card you already added. Always paste the current code when asking for revisions.

Section 13: Change card colors with CSS variables

CSS

CSS variables are named values that make color changes easier to find and adjust.

  1. In the code, look for variables near the top of the CSS or on individual card elements.
  2. Find the variable controlling the back-card background color.
  3. Replace the hex color value with a new hex color.
  4. Publish and check the color on the live page.
  5. Confirm that text contrast remains readable.
:root {
  --card-back-1: #edf4ee;
  --card-back-2: #fff8ed;
}

.flip-card:nth-child(1) {
  --card-back: var(--card-back-1);
}
Check contrast

Changing a background color can make text hard to read. Use a contrast checker and confirm the foreground text still passes readability expectations.

Section 14: Final check

Quality control
  1. Confirm all required cards are present.
  2. Confirm every card flips with mouse, keyboard, and tap where possible.
  3. Check desktop, tablet, and mobile widths.
  4. Confirm image URLs load correctly after publishing.
  5. Check alt text for every meaningful image.
  6. Check attribution for each image or source that needs credit.
  7. Check that the typography and spacing fit the rest of the Tilda page.
  8. Make sure you are using the public published Tilda URL, not the editor URL.

Submission

Final URL

Submit the public URL to your published Tilda page.

Do not submit the Tilda editor URL. The submitted page should include the final flip-card interactive with correct content, images, alt text, attribution, responsive behavior, and working card flips.
