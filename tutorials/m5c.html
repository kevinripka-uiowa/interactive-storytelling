Tutorial M5C

Build a Migration Game in Twine

Create a short interactive story in which a Blackburnian Warbler must balance energy against the time needed to complete its spring migration.

You will use Twine’s Chapbook story format to connect passages, track energy and elapsed days, collect a player-selected stopover length, and reveal an ending based on the combined results.

This story uses a gauntlet structure. Each choice creates a short branch that returns to the main route. This gives the player meaningful consequences without creating an unmanageable number of passages.

What you will build

A compact bird-migration game with three decisions, two tracked variables, a stopover dropdown, an opening image, custom styling, and four possible outcomes.

What you will submit

Your published Twine HTML file named survive-migration.html.

Video walkthrough

Section 1: Open Twine

Twine is available as a desktop application and as a browser-based tool. Either version can create the same kind of story.

Choose how you will open Twine

Step 1
  1. Go to twinery.org.
  2. Select Use in your browser to work online.
Online and desktop Twine store stories differently

The online version saves stories in the local storage of the browser and profile you are using. The desktop version stores its story library on that computer. Neither version automatically synchronizes your work between computers.

Plan for moving between computers

A different browser, browser profile, or computer will have a separate Twine library. Publish or archive your story before leaving the computer so you can import it and continue elsewhere. Clearing browser data can remove stories saved in the online version.

Section 2: Create a Chapbook story

Create the project, then select the story format that determines how your passages, variables, conditions, and styling will work.

Start the story and select Chapbook

Step 2
  1. Create a new story named Survive Migration.
  2. Open the story.
  3. Open Story > Details.
  4. Set the story format to Chapbook.
  5. Open the starting passage and rename it Start.
Use Chapbook syntax throughout this tutorial

Story formats act like different engines for Twine. Harlowe or SugarCube commands may not work in a Chapbook story.

Keep the Chapbook Guide open

Use the Chapbook Guide when you need syntax beyond this tutorial. Its sections cover links, variables and state, conditional display, images, player input, testing, and customization.

Section 3: Plan the structure

Use the passage map to keep the experience compact and make every decision lead somewhere intentional.

The routes split and reconnect before the next major decision. The game remembers consequences through the energy and days variables, while the stopover passage lets the player choose a value from one to seven days.

Section 4: Build the opening slowly

The first passage establishes the starting energy, the interface header, the player’s role, the opening image, and the first link.

Add the Start passage one piece at a time

Step 4

1. Set the starting variables

At the top of the Start passage, enter:

energy: 100
days: 0

This creates an energy variable with a starting value of 100 and a days variable with a starting value of 0.

2. Show both variables in the header

On the next line, enter:

config.header.right: "Energy: {energy} | Days: {days}"

This places both values in the right side of Chapbook’s header. The numbers inside {energy} and {days} update as the player makes choices.

3. Separate variables from visible content

Add a double hyphen on its own line:

--

Everything above the double hyphen belongs to the passage’s variable section. Everything below it is visible to the player.

4. Add the headline

# Survive Migration

The single number sign creates the main heading for the passage.

5. Add the opening image

{embed image: 'https://upload.wikimedia.org/wikipedia/commons/thumb/5/53/Blackburnian_warbler_%2871064%29.jpg/960px-Blackburnian_warbler_%2871064%29.jpg', alt: 'Blackburnian Warbler perched on a branch'}

The image URL tells Chapbook what image to display. The alt text briefly describes the image for people who cannot see it.

6. Explain the player’s role and goal

You are a Blackburnian Warbler migrating north toward your breeding grounds. Your destination is still hundreds of miles away, and every choice will affect your energy and arrival time.

Reach the breeding grounds early enough—and with enough energy—to defend a territory and find a mate.

7. Add the first passage link

[[Begin the journey->Departure]]

The player sees Begin the journey. Selecting it opens a passage named Departure. Twine creates that passage automatically.

Check the Start passage

Test the story. You should see the title, bird image, introductory text, energy and day values, and one link that opens the Departure passage.

Section 5: Add the first decision

Give the player two routes that trade speed against energy, then reconnect both routes at the stopover.

Choose a migration route

Step 5

Departure

# The first major decision

A strong south wind could carry you directly across the Gulf of Mexico. The crossing is shorter, but there is nowhere to rest if the weather changes.

Following the coastline is safer, but it adds hundreds of miles.

[[Cross the Gulf->Cross Gulf]]

[[Follow the coastline->Follow Coast]]

Cross Gulf

energy: energy - 35
days: days + 1
--
A storm forms during the crossing. You fight the wind for hours before finally reaching land.

[[Search for a stopover->Stopover]]

Follow Coast

energy: energy - 20
days: days + 3
--
The coastal route takes longer, but you find favorable winds and avoid the storm over open water.

[[Search for a stopover->Stopover]]

Both routes open Stopover, but the Gulf route is faster and more exhausting while the coastal route takes longer and preserves more energy.

Section 6: Choose stopover days

Let the player decide how long to rest, then use that selection to increase both elapsed time and recovered energy.

Balance arrival time against recovery

Step 6

Stopover

stopoverDays: 1
--
# A shrinking stopover

You reach a patch of shrubs surrounded by roads and buildings. There are insects here, but every day you remain delays your arrival.

Choose how many days to rest:

{dropdown menu for: 'stopoverDays', choices: [1, 2, 3, 4, 5, 6, 7]}

[[Rest for that many days->Rest]]

The dropdown saves the selected number to stopoverDays. Setting it to 1 above the double hyphen gives the menu a starting value.

Rest

stopoverDays: Number(stopoverDays)
days: days + stopoverDays
energy: energy + (stopoverDays * 8)
energy (energy > 100): 100
--
You remain at the stopover for {stopoverDays} days, feeding on insects and rebuilding fat reserves.

Your energy is now {energy}.  
Your migration has taken {days} days.

[[Continue north->Final Push]]

Each stopover day adds one day and restores eight energy points. The final conditional assignment prevents energy from rising above 100.

Convert the selection before calculating

The dropdown stores the selected value as text. Number(stopoverDays) converts it to a number so adding it to days performs arithmetic instead of joining text values.

Test the input

Choose several different stopover lengths. Confirm that one day adds 8 energy and seven days add 56 energy, while the total never exceeds 100.

Section 7: Complete the gauntlet

Add one final choice and send both outcomes to the shared evaluation passage.

Choose when to make the final flight

Step 7

Final Push

# The final push

The breeding grounds are within reach. You can travel overnight in cooler air or wait until daylight, when navigation is easier but predators are more active.

[[Fly through the night->Night Flight]]

[[Wait for daylight->Day Flight]]

Night Flight

energy: energy - 25
days: days + 1
--
You fly through darkness and shifting winds, using the stars and Earth’s magnetic field to stay on course.

[[See how the migration ends->Evaluate]]

Day Flight

energy: energy - 15
days: days + 2
--
You wait for daylight. The route is easier to read, though you spend more time avoiding predators.

[[See how the migration ends->Evaluate]]

Section 8: Create conditional endings

Use both final values to show one outcome based on the bird’s arrival time and remaining energy.

Evaluate the accumulated consequences

Step 8

Open Evaluate and enter:

[if energy >= 70 && days <= 6]
## An early, strong arrival

You reach the breeding grounds with enough energy to defend a territory and attract a mate.

Final energy: {energy}  
Migration time: {days} days

[if energy >= 70 && days > 6]
## A strong but late arrival

You arrive with energy to spare, but many of the best territories have already been claimed.

Final energy: {energy}  
Migration time: {days} days

[if energy >= 55 && energy < 70]
## A difficult arrival

You complete the migration, but your remaining energy makes the breeding season more difficult.

Final energy: {energy}  
Migration time: {days} days

[if energy < 55]
## An exhausted arrival

You reach the breeding grounds depleted. Recovering must come before defending a territory or finding a mate.

Final energy: {energy}  
Migration time: {days} days

Each condition describes a separate, non-overlapping range. Because only one condition can be true, Chapbook displays only one ending.

Use the story stylesheet to change the visual presentation without editing every passage.

These rules add a pale green backdrop, limit the reading width, crop large images consistently, round the image corners, and emphasize links.

Section 10: Test the story

Test several routes and stopover lengths while watching both variables for broken links, incorrect calculations, or incorrect outcomes.

Check every part of the system

Step 10
  1. Select Test so Chapbook opens its Backstage panel.
  2. Watch the energy, days, and stopoverDays variables change after each choice.
  3. Complete several playthroughs using different routes, stopover lengths, and final-flight choices.
  4. Confirm that every passage has a working way forward.
  5. Confirm that only one ending appears in Evaluate.
  6. Check the story map for disconnected or accidental duplicate passages.

Section 11: Save and move the story

Online Twine saves the story only in the current browser and profile. Export a copy before switching computers or submitting your work.

Publish a portable Twine file

Step 11
  1. Open the Build toolbar tab.
  2. Select Publish to File.
  3. Name the file survive-migration.html.
  4. Save it to a location you control, such as OneDrive, Google Drive, or a USB drive.
  5. Open the file in a browser and complete one final playthrough.

Continue on another computer

  1. Open Twine on the second computer.
  2. Choose Import from the Library tools.
  3. Select survive-migration.html.
  4. Open the imported story and continue editing.

Keep a backup while you work

Publish a fresh HTML copy after major changes. The exported file can be opened as a playable story and imported back into Twine if you need to continue on another computer.

Submission

Submit the exported story file after completing and testing the game.
