Tutorial M2 - D1–D2

Build, Publish, and Embed a Custom Master-Detail Interactive

Across two tutorial days, you will build and refine a CSV-driven master-detail interactive, place it under version control, publish it with GitHub Pages, and integrate it into a larger web story.

The example is an interactive about warblers that can be seen in Iowa. Readers begin with a grid of bird thumbnails, then select a bird to see a larger image and detailed information loaded from a CSV file.

AI can write starter code, but you remain responsible for the result. Define the pattern, data, layout, behavior, accessibility, responsiveness, and file structure before generating code. Then inspect, test, troubleshoot, and revise what the AI produces rather than accepting its decisions unchanged.

Day 1: Build locally

Set up the project, connect its data and images, test it through Live Server, and refine the responsive design.

Day 2: Publish and integrate

Use Git and GitHub Pages, update the published project, and choose an iframe or hybrid embed strategy for a larger story.

Day 1: Build and refine the interactive

Set up the project locally, connect the CSV and image assets, troubleshoot file paths, and art-direct the generated design.

Day 1 video walkthrough

Before you start

Download the tutorial files from ICON and make sure you have the software needed to work locally.

Preparation checklist

Have these items ready before you begin.

Setup
  • Download the M2 - D1 asset folder from ICON.
  • Make sure the download includes the images folder, the warbler CSV, the AI prompt, and the generated code ZIP.
  • Use Visual Studio Code on a lab computer, or install it on your own computer.
  • Use Chrome for testing so you can follow the Developer Tools steps shown in the tutorial.
  • Keep the ICON download available. You will move selected files into a separate working folder.
Work from a project folder

A web project is a folder containing files that refer to one another. Keeping the complete project together is necessary for relative file paths, local testing, version control, and publishing.

Section 1: Create the project folder

Create and name the working folder

Step 1
  1. Create a new folder on your Desktop.
  2. Name it master-detail.
  3. Use lowercase letters and a hyphen instead of a space.
Use web-safe file names

URLs are case-sensitive on many servers, and spaces can create awkward encoded URLs. Use lowercase letters, hyphens between words, and no unnecessary punctuation for folders and web files.

Section 2: Open the folder in VS Code

Open the full project context

Step 2
  1. Open Visual Studio Code.
  2. Choose File > Open Folder.
  3. Select the master-detail folder and open it.
  4. In the Explorer panel, create a new file named index.html.
Why index.html?

index.html is the default page a web server looks for when someone visits a folder URL. Each folder can have one default index.html file.

Section 3: Add the starter assets

Move the images and data into the project

Step 3
  1. Return to the ICON download folder.
  2. Move or copy the supplied images folder into master-detail.
  3. Move or copy the warbler CSV file into the root of master-detail.
  4. Return to VS Code and confirm that the Explorer panel shows the new files and folders.
  5. Expand the image folders and verify that the thumbnail images are present.
Watch which copy you edit

The files in the ICON download and the files in your project folder are separate copies. Make all project changes inside master-detail.

Section 4: Understand the CSV

Inspect the project data

Step 4

A CSV is a plain-text representation of a spreadsheet. The first row contains column names, and each later row is one bird record.

  • Open the CSV in VS Code to see its underlying comma-separated structure.
  • Open it in Excel or Google Sheets when you need a more familiar spreadsheet view.
  • Notice which columns contain text, booleans, comma-separated lists, local image names, or external image URLs.
  • Remember that images are separate resources. The CSV stores a path or URL that tells the page where to find each image.
  • Use appropriately sized external image versions rather than linking to unnecessarily large originals.
Keep the CSV as the source of truth

The interactive should read the CSV when the page loads. Do not let an AI tool convert the data into a hard-coded JavaScript object if you expect to update the spreadsheet later.

Section 5: Art-direct the AI prompt

Specify the pattern, data, appearance, and behavior

Step 5

The supplied prompt demonstrates how to direct an AI coding tool. You will use the generated files provided for the tutorial, but you should understand the decisions built into the request.

A. Describe the content and data

  • Identify the project as a master-detail interactive about warblers seen in Iowa.
  • Upload the CSV so the tool can inspect its exact column names.
  • Require the page to read the CSV rather than embedding a converted copy of the data.
  • Allow an appropriate library to parse the CSV.

B. Describe the default state

  • Show square thumbnails for all birds.
  • Use seven birds per row on desktop and five on mobile.
  • Define the thumbnail path and naming convention: lowercase, spaces changed to hyphens, and apostrophes removed.
  • Show the bird name in a tooltip on hover.

C. Describe the detail state

  • Replace the grid with one bird’s detail view after a thumbnail is selected.
  • Include a visible back or close button and keyboard support such as the Escape key.
  • Place the horizontal bird image beside the common and scientific names on desktop.
  • Organize Iowa-specific information and general information according to the CSV fields.
  • Include citations and attribution.

D. Describe technical requirements

  • Make the interactive accessible and responsive.
  • Prepare it for GitHub Pages and eventual placement in a Tilda page.
  • Make it respond to the width of its container, with an optimal maximum width near 1160 pixels.
  • Ask for a complete project folder delivered as a ZIP with separate HTML, CSS, and JavaScript files.
Do not delegate the core decisions

Terminology helps the AI understand the pattern, but terminology alone is not enough. Decide what the reader sees first, how they move to the detail state, what information appears, how it responds across devices, and how the project will be maintained.

Section 6: Add the generated code

Replace the placeholder file and add the supporting files

Step 6
  1. Unzip the supplied code.zip file.
  2. Move its index.html into master-detail.
  3. When asked, replace the empty index.html you created earlier.
  4. Move styles.css and script.js into the project folder.
  5. Confirm in VS Code that all three code files appear beside the CSV and images folder.
  6. Open each file briefly so you can see the separation of structure, appearance, and behavior.
Separate files are easier to manage

The HTML establishes the page structure, the CSS controls appearance and responsive layout, and the JavaScript loads the CSV and builds the interactive behavior.

Section 7: Install and run Live Server

Preview the project through a local web server

Step 7
  1. In VS Code, open Extensions.
  2. Search for Live Server.
  3. Install the widely used Live Server extension.
  4. Return to index.html.
  5. Click Go Live in the VS Code status bar.
  6. Allow the extension to open the project in your browser.

Understand the local address

  • 127.0.0.1 and localhost both refer to your own computer.
  • The number after the colon is the port selected by Live Server.
  • The page exists only on your computer at this stage. It is not yet published online.
Do not rely on double-clicking index.html

Opening the file directly uses a file:// address. Browser security rules can prevent JavaScript from loading a CSV that way. A local server more accurately imitates the environment the project will use after publication.

Section 8: Fix the CSV file path

Connect the JavaScript to the actual data location

Step 8

The starter page displays an error because the generated JavaScript expects the CSV inside a data folder, but the supplied CSV is in the project root.

  1. Open script.js.
  2. Find the constant or variable that stores the CSV path near the beginning of the file.
  3. Remove the incorrect data/ folder from the path.
  4. Leave only the CSV file name, or begin it with ./.
  5. Save the file.
  6. Return to the browser and confirm that Live Server refreshes the page automatically.
// File in the same folder as index.html
const CSV_PATH = "iowa-warblers.csv";

// This is equivalent
const CSV_PATH = "./iowa-warblers.csv";
Use relative paths

A path with no folder name looks in the same folder as the current project file. A leading slash points to the server root and may fail when the project is published inside a repository subfolder.

Section 9: Fix the thumbnail path

Diagnose missing images

Step 9

The data now loads, but the thumbnails remain broken because the prompt referred to an img folder while the supplied folder is named images.

  1. Control-click a broken thumbnail in Chrome and open it in a new tab.
  2. Use the “Cannot GET” message and the address bar to inspect the requested path.
  3. Return to script.js.
  4. Use Command-F to search for img.
  5. Find the line that creates the thumbnail image’s src path.
  6. Change img/thumbnails/ to images/thumbnails/.
  7. Save and verify that the thumbnail grid appears.
  8. Select a bird and press Escape to confirm that the generated close behavior works from the keyboard.
Broken images are often path problems

Check the exact folder name, capitalization, file extension, punctuation, and normalized file name. The code and the file system must match exactly.

Section 10: Optimize and add the detail image

Prepare the missing Prothonotary Warbler image

Step 10

The detail view for one bird still lacks an image because the local images/birds folder does not yet contain the required file.

  1. Confirm that the detail-image path in script.js begins with images/birds/, not img/birds/.
  2. Return to the ICON download and locate the supplied Prothonotary Warbler photograph.
  3. Open the image in Photoshop.
  4. Resize it to approximately 960 pixels on its long dimension.
  5. Convert or embed the sRGB color profile.
  6. Save an optimized copy into master-detail/images/birds.
  7. Use the exact normalized file name expected by the JavaScript.
  8. Return to the browser and verify that the image appears in the detail view.

WebP option

  • Choose File > Save As and select WebP.
  • Use lossy compression near quality 60 as a reasonable starting point.
  • WebP will often produce a substantially smaller file than JPEG at similar visual quality.

JPEG option used by the starter code

  • Choose File > Export > Save for Web.
  • Select JPEG and start near quality 60.
  • Resize to about 960 pixels and enable Convert to sRGB.
  • Save the file into images/birds.
Do not serve the original 5.6 MB image

Resize and compress media for its actual display size. The tutorial’s optimized WebP is roughly 43 KB and the JPEG roughly 106 KB, both far smaller than the original.

Section 11: Test responsive behavior

Use Chrome’s device toolbar

Step 11
  1. Open Chrome Developer Tools with Command-Option-I, or choose View > Developer > Developer Tools.
  2. Use the three-dot menu to dock Developer Tools at the bottom if that gives you more horizontal room.
  3. Turn on the device toolbar.
  4. Drag the responsive viewport from desktop widths down to common phone widths.
  5. Check the thumbnail count, spacing, text size, and detail-view layout at multiple widths.
  6. Test selecting a bird in touch emulation, where hover tooltips are unavailable.
  7. Confirm that the close button and Escape key still work.
Do not test only one desktop and one phone preset

Responsive problems often appear between common device widths. Drag through the full range and watch for abrupt changes, oversized elements, wrapping problems, and horizontal scrolling.

Section 12: Use Developer Tools to inspect the page

Identify the HTML and CSS behind an element

Step 12
  1. Control-click the element you want to change.
  2. Choose Inspect.
  3. Use the Elements panel to identify its HTML element, class, or ID.
  4. Use the Styles panel to see which CSS rules currently apply.
  5. Temporarily turn properties on and off or edit values directly in the browser.
  6. Use the Computed panel when you need to trace where a final value came from.
  7. After finding a better value, make the permanent change in styles.css.
Browser edits are temporary

Developer Tools are a safe place to experiment. Refreshing the page erases those changes, so copy the successful rule or value into your project file and save it.

Section 13: Adjust typography

Change paragraphs and chips to sans serif

Step 13
  1. Open styles.css.
  2. Add a rule for paragraph elements.
  3. Use a system sans-serif stack such as Arial, Helvetica, and the generic sans-serif keyword.
  4. Inspect one of the status labels and identify its class as chip.
  5. Add .chip to the same selector list.
  6. Save and verify that both paragraphs and chips change.
p,
.chip {
  font-family: Arial, Helvetica, sans-serif;
}
Learn enough syntax to direct the code

A class selector begins with a period. Multiple selectors can share one declaration block when they need the same styling.

Section 14: Adjust the food grid

Show more food icons per row

Step 14

The generated food icons are too large and compete with the bird photograph. The list uses CSS Grid, so you can change how many equal-width columns it creates.

  1. Inspect the food-icon list and identify its class as food-list.
  2. In Developer Tools, change grid-template-columns and compare the result.
  3. Set the main desktop rule to three columns.
  4. Search styles.css for every .food-list rule.
  5. At the media query for screens up to about 700 pixels, use four columns.
  6. At the media query for screens up to about 420 pixels, use three columns.
  7. Save and drag through the responsive range again.
.food-list {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}

@media (max-width: 700px) {
  .food-list { grid-template-columns: repeat(4, 1fr); }
}

@media (max-width: 420px) {
  .food-list { grid-template-columns: repeat(3, 1fr); }
}
Read a media query as a condition

@media (max-width: 700px) means: when the viewport is 700 pixels wide or narrower, use these declarations to override the default rules.

Section 15: Refine responsive type and color

Reduce the bird name and add heading color

Step 15

A. Reduce the detail heading

  1. Inspect the selected bird’s name.
  2. Identify the CSS rule controlling the detail-view heading.
  3. Notice that its font size uses clamp().
  4. Reduce the maximum value to about 2.5rem.
  5. Save and check the heading at desktop and mobile widths.
.bird-heading h2 {
  font-size: clamp(2rem, 4vw, 2.5rem);
}

B. Add a purposeful heading color

  1. Choose a color that belongs to the visual system for the complete explainer.
  2. Add a color rule for the appropriate h3 headings.
  3. Check the foreground and background combination for sufficient contrast.
  4. Avoid adding a random accent color only because it looked appealing in isolation.
How clamp() works

The first value is the minimum size, the middle value is the preferred fluid size, and the third value is the maximum. The browser scales within those limits.

Section 16: Refine the introduction layout

Balance the title and align the introduction

Step 16
  1. Find the selector for the introductory h1.
  2. Add text-wrap: balance to improve the distribution of words across short headline lines.
  3. Inspect the parent header with the class intro.
  4. Change its text alignment from center to left.
  5. Use the same maximum width as the main content so the introduction aligns with the interactive below it.
  6. Adjust the bottom margin to preserve enough space before the thumbnail grid.
  7. Save and check the layout at several widths.
.intro {
  max-width: 1040px;
  margin: 0 auto 32px;
  text-align: left;
}

.intro h1 {
  text-wrap: balance;
}
Reuse the project’s existing measurements

When two regions should align, inspect the working region and reuse its maximum width or spacing rather than guessing unrelated values.

Section 17: Final check

Review the local project before Day 2

Step 17
  • Confirm that Live Server loads the page without a data error.
  • Confirm that all bird thumbnails appear.
  • Open several detail views and check the text, images, food icons, and back control.
  • Confirm that the Prothonotary Warbler detail image loads from images/birds.
  • Use the Tab and Escape keys to test basic keyboard behavior.
  • Drag through desktop, tablet, and phone widths.
  • Check for horizontal scrolling, awkward line breaks, oversized icons, and abrupt responsive changes.
  • Confirm that your edits were made in the master-detail project, not in the original download folder.
  • Keep index.html, styles.css, script.js, the CSV, and the full images folder together.
Stop Live Server when finished

Click the port indicator in the VS Code status bar when you are done testing. The local server is only a development tool; the next tutorial will publish the project online.

Day 2: Publish and integrate the interactive

Turn the local project into a Git repository, publish it with GitHub Pages, update it through commits, and place it into a larger story without breaking its assets or styles.

Day 2 video walkthrough

Before you start Day 2

Open the completed master-detail folder from Day 1 in VS Code. You will also need a GitHub account and permission to edit the larger story where the interactive will appear.

Preparation checklist

Confirm the project works locally before publishing it.

Setup
  • Open the complete master-detail folder in VS Code.
  • Run Live Server and confirm that the thumbnail grid, detail views, CSV, and images still load.
  • Create or sign in to a GitHub account.
  • Know where the interactive will be integrated, such as a Tilda page or another web builder that accepts custom HTML.
Keep the local and published versions distinct

Live Server shows the files on your computer. GitHub Pages shows a separate published copy. Saving locally does not update the public version until you commit and sync the changes.

Section 1: Check for Git and install it if needed

Prepare VS Code for source control

Step 1

Open the Source Control panel in VS Code. If Git is installed, VS Code will offer to initialize the project repository. If it is not installed, VS Code will direct you to installation instructions.

  1. Open the Source Control panel in VS Code.
  2. On Windows, use the Git for Windows standalone installer.
  3. On macOS, open Terminal > New Terminal in VS Code and run xcode-select --install.
  4. Approve the installation of Apple’s Command Line Tools.
  5. Close and restart VS Code after Git finishes installing.
  6. Reopen the master-detail folder and approve Workspace Trust when prompted.
Git and GitHub are different

Git tracks versions inside the project folder on your computer. GitHub stores a remote copy online and can publish that copy as a website.

Section 2: Initialize the Git repository

Start tracking the project

Step 2
  1. Make sure the complete project folder is open in VS Code.
  2. Open Source Control and select Initialize Repository.
  3. Enter Initial commit as the commit message.
  4. Select Commit.
A commit is a named checkpoint

Each commit records the state of the tracked files at that moment. Useful commit messages briefly describe the completed change.

Section 3: Publish the repository to GitHub

Create the remote copy

Step 3
  1. Select Publish Branch in VS Code.
  2. Allow VS Code to open GitHub and authorize the connection.
  3. Sign in with your GitHub credentials.
  4. Choose a public repository for this course project.
  5. Open the new repository on GitHub and confirm that the project files appear.
The repository is not yet a website

Publishing the branch copies the files to GitHub. GitHub Pages must still be enabled before the browser can display the project as a web page.

Section 4: Enable GitHub Pages

Deploy the main branch

Step 4
  1. Open the repository on GitHub.
  2. Choose Settings.
  3. Select Pages in the left navigation.
  4. Under Build and deployment, choose Deploy from a branch.
  5. Select the main branch and the root folder, then save.
  6. Open the Pages URL after GitHub finishes building the site.
https://YOUR-USERNAME.github.io/master-detail/
A temporary 404 can be normal

The first deployment may take a few minutes. Refresh after GitHub completes the build rather than changing working code immediately.

Section 5: Add the missing Wilson’s Warbler record

Make a visible project update

Step 5
  1. Open the project CSV in Excel or another spreadsheet editor.
  2. Use the supplied Wilson’s Warbler information to add one complete row.
  3. Preserve the existing column order and data formats.
  4. Save the CSV inside the master-detail project folder.
  5. Check the Live Server version and confirm that Wilson’s Warbler appears.
  6. Refresh the GitHub Pages version and notice that it has not changed yet.
The CSV remains the source of truth

Because the interactive loads the spreadsheet when the page starts, adding one valid row updates the local visualization without editing the JavaScript.

Section 6: Commit and sync the update

Send the changed CSV to GitHub

Step 6
  1. Return to Source Control in VS Code.
  2. Review the changed CSV listed under Changes.
  3. Enter a message such as Add Wilson's Warbler.
  4. Select Commit.
  5. Select Sync Changes to push the commit to GitHub.
  6. After GitHub Pages rebuilds, refresh the public site and confirm the new bird appears.
Commit, then sync

A commit records the checkpoint locally. Sync sends that commit to GitHub. GitHub Pages then rebuilds the public website from the updated repository.

Section 7: Troubleshoot delayed changes and browser caching

Separate deployment delay from cached files

Step 7
  1. Give GitHub Pages time to rebuild after syncing changes.
  2. Open Developer Tools in Chrome.
  3. In the Network panel, enable Disable cache while Developer Tools remains open.
  4. Alternatively, use Empty Cache and Hard Reload from the browser’s reload menu.
  5. Open the public page in a new tab when needed to test a fresh request.
Do not assume the code failed

A working local update that does not appear publicly may be waiting for deployment or may be hidden by the browser’s cached copy.

Section 8: Test a standard iframe embed

Embed the published page as a separate document

Step 8
  1. Add a custom HTML block in Tilda or your chosen builder.
  2. Copy the GitHub Pages URL for the interactive.
  3. Use it as the iframe’s src.
  4. Set the iframe to display as a block, center it, use the full available width, limit its maximum width, assign a height, and remove the border.
  5. Publish the story page and test both the thumbnail grid and detail state.
<iframe
  src="https://YOUR-USERNAME.github.io/master-detail/"
  title="Warblers that can be seen in Iowa"
  style="display:block; margin:0 auto; width:100%; max-width:1160px; height:100vh; border:0;"
></iframe>
An iframe needs a predictable height

The master-detail project changes height between states and may require its own internal scrollbar. A full-screen map or visualization with a fixed viewport is usually a better candidate for a pure iframe.

Section 9: Choose between an iframe and a hybrid embed

Match the integration method to the interactive

Step 9

Use a pure iframe when:

  • The interactive has a stable or viewport-based height.
  • It should remain isolated from the story page’s CSS and JavaScript.
  • An internal scrollbar will not harm the experience.

Use a hybrid embed when:

  • The content height changes substantially between states.
  • You need the interactive to participate in the parent page’s natural scrolling.
  • You can convert local asset paths to absolute hosted URLs and control CSS conflicts.
Hybrid means hosted assets plus pasted structure

The HTML structure and initialization scripts are pasted into the builder, while the CSV, images, and other assets remain hosted in the GitHub Pages project.

Section 10: Build the hybrid embed

Paste only the parts the builder needs

Step 10
  1. Delete or disable the test iframe block.
  2. Open index.html in VS Code.
  3. Copy the complete <main> element used by the interactive.
  4. Copy the required script tags at the end of the page.
  5. Paste them into the builder’s custom HTML block.
  6. Bring in the project’s CSS, either by pasting the relevant styles or linking to the hosted stylesheet.
  7. Publish and inspect what loads before making additional changes.
Do not paste a second document skeleton

The builder already supplies <html>, <head>, and <body>. Paste the interactive’s content and required resources, not an entire standalone page inside another page.

Section 11: Convert relative asset paths to absolute URLs

Point the hybrid embed back to GitHub Pages

Step 11

Relative paths are resolved from the page where the code is running. After the script is pasted into Tilda, a path such as iowa-warblers.csv points toward Tilda rather than the GitHub repository.

  1. Copy the GitHub Pages base URL for the repository.
  2. In script.js, replace the relative CSV path with its full public URL.
  3. Update generated thumbnail paths and local detail-image paths in the same way.
  4. Check the CSV for any local image paths that also need full URLs.
  5. Leave external image URLs unchanged.
  6. Commit and sync the path changes.
const BASE_URL = "https://YOUR-USERNAME.github.io/master-detail/";
const CSV_PATH = `${BASE_URL}iowa-warblers.csv`;

// Examples used when building image src values
`${BASE_URL}images/thumbnails/${fileName}`
`${BASE_URL}images/birds/${fileName}`
Test the asset URL directly

Paste a suspected CSV or image URL into the browser. If it opens or downloads, the resource exists. If the embed still fails, inspect the console and the code that requests it.

Section 12: Stop the embedded interactive from jumping to the page top

Remove page-level scrolling that no longer fits the context

Step 12

The generated JavaScript uses window.scrollTo() when opening or closing the detail view. Once the interactive sits inside a longer story page, that command scrolls the entire browser window rather than only the interactive.

  1. Search script.js for scrollTo.
  2. Locate the calls used when opening and closing the detail state.
  3. Comment them out or remove them.
  4. Commit and sync the change.
  5. Retest the interaction inside the complete story page.
// window.scrollTo({ top: 0, behavior: "smooth" });
A more targeted option

When repositioning is useful, scroll the interactive container into view with document.querySelector('#app').scrollIntoView() rather than sending the whole page to its absolute top.

Section 13: Prevent the interactive CSS from changing the story page

Namespace broad selectors

Step 13

Pasting a standalone stylesheet into a builder can change unrelated headings, paragraphs, body styles, and layout rules. Scope the interactive’s selectors to its wrapper, such as #app.

  1. Identify the interactive’s outer wrapper, such as <div id="app">.
  2. Find broad CSS selectors including p, h2, h3, img, and the universal selector *.
  3. Prefix selectors that belong only to the interactive with #app.
  4. Remove or rewrite page-wide body and root-level layout rules that should not affect the builder.
  5. Retest the story typography, spacing, and the interactive itself.
  6. Commit and sync the CSS corrections.
/* Too broad in a pasted embed */
p { font-family: Arial, sans-serif; }

/* Scoped to the interactive */
#app p { font-family: Arial, sans-serif; }

/* Scope box sizing without changing the whole page */
#app, #app * { box-sizing: border-box; }
Plan namespacing before generation

For future custom snippets, require every class and selector to be scoped to a unique wrapper. Retrofitting a large stylesheet after embedding is slower and easier to get wrong.

Section 14: Final integration check

Review the published project and complete story

Final
  • Confirm the GitHub Pages URL loads without a 404 or missing assets.
  • Confirm Wilson’s Warbler appears in the published data.
  • Open several detail views and verify all thumbnail, bird, and food images.
  • Test the embedded version at desktop, tablet, and phone widths.
  • Confirm opening and closing details does not jump to the top of the story.
  • Check that the interactive stylesheet does not change unrelated story text or layout.
  • Make the interactive’s typography, colors, and spacing consistent with the surrounding explanatory story.
  • Use clear commit messages for the final fixes and sync all changes to GitHub.
The interactive is one part of a larger explanation

Technical integration is complete only when the hosted assets, interaction behavior, responsive layout, accessibility, and visual system all work within the full story.
