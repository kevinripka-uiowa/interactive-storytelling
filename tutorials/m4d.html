Build a Scroll-Driven Map with Mapbox

Create a guided map story about a hypothetical neotropical migrant. The map will move from winter and breeding ranges to migration routes, a Gulf crossing, urban buildings, and mountain terrain.

Mapbox Studio builds the map; config.js choreographs the story. Studio controls the basemap and custom geographic layers. The Storytelling template uses Scrollama to connect scrolling chapters to camera movement and layer changes.

What you will build

A full-page scrollytelling map with custom polygon and line layers, chapter-based opacity changes, pitched 3D views, and an embedded presentation in Tilda.

What you will submit

Your published Tilda page and the public GitHub repository that contains the complete Mapbox Storytelling project.

Video walkthrough

Follow the recorded demonstration while using the written steps and supplied code below.

Before you start

Prepare the accounts, software, data, and project materials needed for the tutorial.

Preparation checklist

Setup
  • Sign in to Mapbox.
  • Install Visual Studio Code and the Live Server extension.
  • Download the supplied GeoJSON files for the breeding range, winter range, and migration route.
  • Download the supplied birds.png image.
  • Have a GitHub account and a Tilda page ready.
  • Mapbox Storytelling template
  • Mapbox location helper

Section 1: Download and inspect the template

The template provides the scrolling system, map setup, and chapter logic. Your primary work will happen in config.js.

Open the project in VS Code

Step 1
  1. Download the ZIP from the Mapbox Storytelling repository.
  2. Unzip it and rename the folder scroll-map.
  3. Open the complete folder in Visual Studio Code.
  4. Keep index.html, config.js, and the supporting project files. You may remove sample assets you will not use.
  5. Start Live Server from index.html.
Do not rewrite the template JavaScript

The project already loads Mapbox GL JS and Scrollama and contains the code that connects chapters to the map. For this tutorial, edit config.js and use the existing template.

Section 2: Create a restricted Mapbox token

The map will not load until the project has a public Mapbox access token.

Create a project-specific token

Step 2
  1. Open the access-token area of your Mapbox account.
  2. Create a new public token and give it a clear name such as M4D Scroll Map.
  3. Restrict the token to localhost so the project works with Live Server.
  4. Add your GitHub Pages domain, such as yourusername.github.io.
  5. Create the token and paste it into config.js.
accessToken: 'YOUR_PUBLIC_MAPBOX_TOKEN',
The token will be visible in the browser

This is a client-side map, so use a public token with limited permissions and URL restrictions. Do not use a secret token.

Section 3: Create a custom Mapbox Studio style

The custom style will contain the basemap plus the geographic layers used by the story.

Start with Mapbox Standard

Step 3
  1. Open the Mapbox Studio style editor.
  2. Create a new style and choose Mapbox Standard.
  3. Leave the default basemap settings unless they interfere with the story.
  4. Rename the style Neotropical Birds.

You may change label visibility, colors, or other basemap settings later, but the tutorial focuses on adding and controlling custom data layers.

Section 4: Add and style the custom layers

Upload three GeoJSON datasets and name the resulting layers exactly as they will appear in config.js.

Add the breeding, winter, and migration layers

Step 4

Polygon layers

  • Upload breedingrange.geojson.
  • Use an orange fill and remove or reduce the stroke.
  • Name the layer breeding-range.
  • Upload the winter-range file, use a blue fill, and name it winter-range.

Line layer

  • Upload the migration-route GeoJSON.
  • Choose a visible line color and width.
  • Name the layer migration-route.
Set the initial opacity to zero

Set the relevant opacity property of all three story-controlled layers to 0. The chapters will reveal them later. A fill layer may have separate fill and outline settings.

Section 5: Publish the style

The Storytelling project must point to a published Mapbox style.

Copy the Style URL

Step 5
  1. Click Save and publish.
  2. Wait for the uploaded datasets to finish processing.
  3. If Studio reports a temporary publishing error, refresh and try again.
  4. Open the style’s Share panel.
  5. Copy the Style URL beginning with mapbox://styles/.
style: 'mapbox://styles/your-username/your-style-id',

Section 6: Configure the project

The main configuration object stores project-wide settings and an array of chapter objects.

Set the story-level properties

Step 6
var config = {
  style: 'mapbox://styles/your-username/your-style-id',
  accessToken: 'YOUR_PUBLIC_MAPBOX_TOKEN',
  showMarkers: false,
  theme: 'light',
  title: 'Dangers of Neotropical Migrants',
  subtitle: 'Birds face obstacles as they migrate from Central and South America to breed in the United States and Canada',
  chapters: [
    // Chapter objects go here
  ]
};
  • style connects the project to your published Studio style.
  • showMarkers: false removes the template’s default chapter markers.
  • theme controls the chapter-card appearance.
  • title and subtitle create the introduction shown before the chapters.
  • chapters is an array containing one object for each story section.
Do not add 3D terrain yet

You will add use3dTerrain: true later, when the story reaches the mountain chapter and the setting has a clear purpose.

Section 7: Construct the opening chapter

Build this first chapter property by property. Do not paste a completed chapter object.

Start the chapter object

Step 7A

Inside the chapters array, begin an object with an opening curly brace. Add a unique ID and choose where the text card will appear.

{
  id: 'earth',
  alignment: 'left',
  • id identifies the chapter in the template. Use a short, unique name without spaces.
  • alignment positions the story card. This chapter uses the left side of the screen.
  • End each property with a comma because more properties follow.

Add the visible story content

Step 7B

Use the values in 1.txt to add the chapter title and description. Type the property names yourself, then copy only the supplied values.

  title: 'Neotropical Migrants',
  description: 'PASTE THE DESCRIPTION FROM 1.txt',

Add the supplied bird image after the description:

  image: 'images/birds.png',
The description supports HTML

Add a <br> before the final sentence and wrap that sentence in <b> tags. Because Let’s contains an apostrophe, escape it as Let\'s when the full description uses single quotation marks.

Create the nested location object

Step 7C

The camera settings belong inside a second object named location. Use the center, zoom, pitch, and bearing values supplied in 1.txt.

  location: {
    center: [-80.5, 20],
    zoom: 2,
    pitch: 0,
    bearing: 0
  },
  • center is an array in [longitude, latitude] order.
  • zoom: 2 creates a broad geographic view.
  • pitch: 0 looks straight down at the map.
  • bearing: 0 places north at the top.

Add the transition and initial layer states

Step 7D

Add the camera transition, then create an array of layer instructions. The first chapter explicitly hides all three custom layers so the story starts from a predictable state.

  mapAnimation: 'flyTo',
  onChapterEnter: [
    { layer: 'breeding-range', opacity: 0 },
    { layer: 'winter-range', opacity: 0 },
    { layer: 'migration-route', opacity: 0 }
  ]
}
  • mapAnimation: 'flyTo' creates a smooth geographic transition.
  • onChapterEnter is an array because one chapter can change several layers.
  • Each item in that array is an object naming a Studio layer and its target opacity.
  • The final property does not need a trailing comma.
Check the object before continuing

Confirm that the braces and brackets close in the reverse order in which they opened: layer object, array, chapter object.

Section 8: Use the Mapbox location helper

Before adding more chapters, learn how to find the camera values that define each map view.

Find and test a location

Step 8
  1. Open the Mapbox location helper.
  2. Search for a place or move the map to the view you need.
  3. Zoom to set the geographic scale.
  4. Hold the appropriate map control and drag to test pitch and bearing.
  5. Copy the resulting center, zoom, pitch, and bearing values into a chapter’s location object.

Position and scale

  • Center: Longitude and latitude at the middle of the map.
  • Zoom: How much geographic area is visible.

Viewing angle

  • Pitch: The angle between a top-down and tilted view.
  • Bearing: The direction the camera faces. North is 0, east is 90, south is 180, and west is 270.
Use camera changes to communicate

Zooming out can establish a system, zooming in can reveal a local obstacle, and a high pitch can make terrain or buildings legible. Do not change the camera only for visual novelty.

Section 9: Add and modify the remaining chapters

For each stage, paste the base chapter object shown in the tutorial. Then complete the separate addition below it so you understand what changes the map state.

Chapter 2: Breeding Range

Paste + Add

First: Paste this base chapter after the opening chapter. Make sure a comma separates the two chapter objects.

{
  id: 'breeding-range',
  alignment: 'right',
  title: 'Breeding Range',
  description: 'During the summer, our hypothetical neotropical migrant breeds across eastern Canada, where long days and abundant insects provide the food needed to raise young.',
  location: {
    center: [-70, 49.88223],
    zoom: 3,
    pitch: 0,
    bearing: 0
  },
  mapAnimation: 'flyTo'
}

Then add the layer change

The base chapter moves the camera, but it does not yet reveal the breeding-range polygon. Add a comma after mapAnimation, then add this property before the chapter’s closing brace:

onChapterEnter: [
  { layer: 'breeding-range', opacity: 0.6, duration: 800 }
]

This makes the polygon partially opaque over 800 milliseconds so the basemap remains visible beneath it.

Chapter 3: Winter Range

Paste + Add

First: Paste this base chapter after the Breeding Range chapter.

{
  id: 'winter-range',
  alignment: 'left',
  title: 'Winter Range',
  description: 'When the breeding season ends, the bird returns to its winter range in southern Central America and northern South America, where warmer conditions provide food throughout the colder months.',
  location: {
    center: [-74.87590, 8.69840],
    zoom: 3,
    pitch: 0,
    bearing: 0
  },
  mapAnimation: 'flyTo',
  onChapterEnter: [
  ]
}

Then swap the visible range

Add these two objects inside the empty onChapterEnter array:

{ layer: 'breeding-range', opacity: 0 },
{ layer: 'winter-range', opacity: 0.6, duration: 800 }

The first instruction hides the previous chapter’s layer. The second reveals the winter range. Each chapter should define the map state the viewer needs at that moment.

  location: {

    zoom: 6.84,
    pitch: 79.5,
    bearing: 0
  },
  mapAnimation: 'flyTo',

{

  alignment: 'left',
  title: 'Across the Gulf',

Then direct and slow the Gulf crossing

In the Across the Gulf chapter, change the existing bearing from 0 to 15. Then add speed inside the same location object:

bearing: 15,
speed: 0.25

The bearing points the camera slightly east of north. The lower speed makes the over-water transition feel like part of the story instead of an instantaneous jump.

Chapter 7: Buildings

Paste + Add

{

  onChapterEnter: []

Then add rotation

Add this property at the chapter level, before location:

rotateAnimation: true,

Keep the empty onChapterEnter array. The template’s rotation behavior may depend on that array being present even when the chapter does not change a custom data layer.

Chapter 8: Mountains

Paste + Add

First: Paste this base chapter and preview it before changing the main configuration. The camera should tilt toward the landscape, but the elevation may still look flat.

{
  id: 'mountain-terrain',
  alignment: 'left',
  title: 'Mountains',
  description: 'Farther north, the bird must cross mountainous terrain. Cold temperatures, storms, and limited food can slow migration and force birds to spend more time searching for safe places to rest and refuel.',
  location: {

Then enable terrain

Return to the main config object, above the chapters array, and add:

Refresh the project and compare the mountain chapter before and after the setting. This is a global option, but you are adding it now because the story has reached the chapter that requires it.

Inspect the map-state logic

  • The second Breeding Range chapter reveals the breeding polygon after the bird completes the northbound journey.
  • The Fall Migration chapter hides the breeding range, reveals the winter range, and changes the bearing to 180 so the camera faces south.
Test in both directions

Scroll forward and backward through every chapter. A layer instruction that works while moving down the page may leave an incorrect state when the viewer scrolls back up.

Section 10: Publish with GitHub Pages

The Tilda page will embed the map from a public GitHub Pages URL.

Push and enable Pages

Step 10
  1. Open Source Control in VS Code and initialize a repository.
  2. Commit the complete project.
  3. Publish the branch as a public GitHub repository.
  4. If GitHub blocks the push because it detects the public Mapbox token, open the provided review link and allow the token only after confirming that it is public, restricted, and intended for the browser.
  5. Open the repository settings and enable GitHub Pages from the main branch.
  6. Test the public Pages URL after deployment finishes.
Do not approve an unrestricted or secret token

The exception is appropriate only for the deliberately public browser token created for this project and restricted to your allowed domains.

Section 11: Embed the story in Tilda

Use a full-height iframe and prevent it from capturing pointer interaction before it reaches the top of the browser.

Add a T123 HTML block

Step 11
  1. Add a custom HTML block to the Tilda page.
  2. Paste the code below into the block.
  3. Replace YOUR_MAP_URL with your GitHub Pages URL.
  4. Publish the Tilda page and test the transition into the iframe.
<style>
  #scroll-map-embed {
    width: 100%;
    height: 100vh;
  }

  #scroll-map-embed iframe {
    width: 100%;
    height: 100%;
    border: 0;
    pointer-events: none;
  }

  #scroll-map-embed.is-active iframe {
    pointer-events: auto;
  }
</style>

<script>
  document.addEventListener('DOMContentLoaded', () => {
    const embed = document.getElementById('scroll-map-embed');

    if (!embed) return;

    function updateIframeInteraction() {
      const top = embed.getBoundingClientRect().top;
      embed.classList.toggle('is-active', top <= 0);
    }

    updateIframeInteraction();

    window.addEventListener('scroll', updateIframeInteraction, {
      passive: true
    });

    window.addEventListener('resize', updateIframeInteraction);
  });
</script>

<div id="scroll-map-embed">
  <iframe
    src="YOUR_MAP_URL"
    title="Dangers of Neotropical Migrants">
  </iframe>
</div>
Why disable pointer events?

Before the iframe reaches the top of the viewport, wheel and touch interaction should continue moving the Tilda page. Once the embed reaches the top, the script enables interaction inside the map story.
