Tutorial M4 - Guided Map

Build a Scroll-Driven Bird Map with Mapbox

In this tutorial, you will create a guided map story about bird migration. As the reader scrolls, the map will move from a continental overview to stopover habitat, an urban hazard, mountain terrain, and a breeding range.

You will create and style the geographic layers in Mapbox Studio. You will then use the Mapbox Storytelling template and edit only config.js to control the story text, camera position, 3D terrain, and layer visibility.

Mapbox Studio builds the map; config.js directs the story. Studio controls the basemap and geographic layers. The configuration file controls where the camera moves and which prepared layers become visible in each chapter.

What you will build

A full-page, scroll-driven bird migration story with custom points, lines, and polygons; pitched 3D views; mountain terrain; and chapter-based layer changes.

What you will submit

The public GitHub Pages URL and the complete project repository. Your project should use the standard template without adding custom JavaScript.

Before you start

Prepare the accounts, software, story material, and geographic data used in the project.

Preparation checklist

Setup
  • Create a Mapbox account and locate your public access token.
  • Open Mapbox Studio.
  • Install Visual Studio Code and the Live Server extension.
  • Create or download three small GeoJSON files: a migration route, bird observation or stopover points, and a breeding or habitat range.
  • Prepare a short story of four to six chapters. Each chapter should have a geographic reason to move the map.
  • Prepare any photographs and record their sources, licenses, and alt text.
Use a public token, not a secret token

A public Mapbox token normally begins with pk.. It will be visible in the published project. Never place a secret token in a public repository.

Section 1: Understand the workflow

This project uses three connected pieces, but you will write story-specific content in only one file.

Separate data, design, and choreography

Concept
  • GeoJSON: Stores the bird locations, routes, and range boundaries.
  • Mapbox Studio: Uploads the data, converts it into hosted map data, styles each layer, and publishes a custom map style.
  • config.js: Stores the story chapters, camera locations, transition settings, and instructions for showing or hiding prepared layers.
Do not add raw GeoJSON in config.js

The standard Storytelling template expects custom layers to already exist in the Mapbox Studio style. The configuration file changes their opacity as the reader moves through the story.

Section 2: Prepare the bird data

Use a different geometry for each story job

Step 2
  • Points: Stopover sites, nesting locations, collision reports, or notable observations.
  • Lines: A simplified migration route or movement corridor.
  • Polygons: Breeding range, wintering range, wetland habitat, or a conservation area.

Keep the example data small. Every feature should include useful properties such as name, type, season, or description.

{
  "type": "Feature",
  "properties": {
    "name": "Iowa River Corridor",
    "type": "stopover habitat"
  },
  "geometry": {
    "type": "Point",
    "coordinates": [-91.53, 41.66]
  }
}
Use demonstration data responsibly

Do not draw a migration route and present it as a precise scientific track. Label simplified or fictional data clearly, or use authoritative data and cite it.

Section 3: Create a custom Mapbox style

Start with Mapbox Standard

Step 3
  1. In Mapbox Studio, open the Styles area.
  2. Choose New style.
  3. Use Mapbox Standard as the basemap.
  4. Rename the style something specific, such as Bird Migration Story.
  5. Adjust the basemap theme and label density so the custom bird layers will remain dominant.
Mapbox Standard includes 3D context

At a close zoom and high pitch, Standard can display 3D buildings and detailed landmarks without requiring you to add a custom building layer.

Section 4: Add and style the custom layers

Upload each dataset and name every layer clearly

Step 4
  1. Choose Add new layer, then upload the first GeoJSON file.
  2. Allow Mapbox Studio to convert the uploaded data into a tileset.
  3. Choose the correct layer type: circle or symbol for points, line for routes, and fill for ranges.
  4. Give the layer a short ID that will be easy to copy into config.js.
  5. Repeat for the remaining datasets.
migration-route
stopover-sites
urban-hazards
breeding-range

Style for hierarchy

  • Make the migration route prominent enough to follow at a continental zoom.
  • Give points a visible stroke so they remain legible over varied basemap colors.
  • Use partial opacity for polygons so readers can still see geographic context.
  • Use more than color when possible. A dashed route or outlined polygon adds a second visual cue.

Section 5: Prepare the layers for chapter control

Set story-controlled layers to zero opacity

Step 5
  1. Select a custom layer that should be hidden when the story first loads.
  2. Set its relevant opacity property to 0.
  3. For a circle layer, check both circle opacity and stroke opacity.
  4. For a line layer, set line opacity to 0.
  5. For a fill layer, set fill opacity to 0 and consider whether the outline also needs to begin hidden.
  6. Repeat for every layer that chapters will reveal later.
Do not use the eye icon to hide the layer

The Storytelling template changes paint opacity. A layer disabled in Studio may remain unavailable even when config.js tries to reveal it.

Section 6: Publish the Mapbox style

Copy the style URL and layer IDs

Step 6
  1. Click Publish in Mapbox Studio.
  2. Review the changes and confirm the publication.
  3. Open the style’s sharing or developer resources.
  4. Copy the Style URL. It should begin with mapbox://styles/.
  5. Record the exact IDs of all custom layers. Spelling and capitalization must match.
mapbox://styles/your-username/your-style-id

Section 7: Download and open the Storytelling template

Use the official Mapbox repository

Step 7
  1. Open the Mapbox Storytelling repository.
  2. Choose Code, then Download ZIP.
  3. Unzip the project and rename the folder for your story.
  4. Open the complete folder in Visual Studio Code.
  5. Open config.js.template or the supplied configuration example.
  6. Save a working copy as config.js if the downloaded version does not already include one.
  7. Start Live Server from index.html.
Leave the template JavaScript alone

For this tutorial, do not edit the application code. Your work should be limited to Mapbox Studio, config.js, story images, and minor visual changes only when directed.

Section 8: Add the access token and custom style

Configure the story-level settings

Step 8
var config = {
  style: 'mapbox://styles/your-username/your-style-id',
  accessToken: 'YOUR_PUBLIC_MAPBOX_TOKEN',
  showMarkers: false,
  markerColor: '#37634e',
  theme: 'light',
  use3dTerrain: true,
  title: 'A Bird\'s Journey North',
  subtitle: 'Migration connects habitats across a continent',
  byline: 'By Your Name',
  footer: 'Sources and image credits go here.',
  chapters: [
    // Story chapters go here
  ]
};
  • Paste your public token into accessToken.
  • Paste the published custom Style URL into style.
  • Set use3dTerrain to true so pitched mountain views use elevation.
  • Use showMarkers: false when custom point layers already identify locations.

Section 9: Build the opening chapter

Introduce the full migration system

Step 9
{
  id: 'continental-overview',
  alignment: 'left',
  hidden: false,
  title: 'A continental journey',
  image: './images/warbler.jpg',
  description: 'Each spring, migratory birds move through a connected chain of habitats.',
  location: {
    center: [-96.5, 39.5],
    zoom: 3.4,
    pitch: 0,
    bearing: 0
  },
  mapAnimation: 'flyTo',
  rotateAnimation: false,
  callback: '',
  onChapterEnter: [
    { layer: 'migration-route', opacity: 0.85, duration: 1000 }
  ],
  onChapterExit: []
}

Chapter anatomy

  • id must be unique and should use lowercase words separated by hyphens.
  • alignment controls where the text panel sits over the map.
  • location controls center, zoom, pitch, and bearing.
  • mapAnimation can use flyTo, easeTo, or jumpTo.
  • onChapterEnter reveals or mutes prepared Studio layers.
Longitude comes first

Mapbox coordinates use [longitude, latitude]. Reversing them usually sends the camera to the wrong place or outside the valid map range.

Section 10: Add 3D terrain and city views

Use pitch and bearing to reveal depth

Step 10

The global use3dTerrain: true setting enables terrain. Individual chapters determine whether the reader can actually see the depth.

{
  id: 'mountain-passage',
  alignment: 'right',
  title: 'Crossing the mountains',
  description: 'Elevation changes the route and concentrates birds in usable corridors.',
  location: {
    center: [-110.75, 43.75],
    zoom: 9.2,
    pitch: 65,
    bearing: 28,
    speed: 0.7,
    curve: 1.3
  },
  mapAnimation: 'flyTo',
  rotateAnimation: true,
  callback: '',
  onChapterEnter: [],
  onChapterExit: []
}

For an urban chapter, move to a close zoom in a city and keep a high pitch. Mapbox Standard can display 3D buildings automatically where building data is available.

location: {
  center: [-87.6298, 41.8781],
  zoom: 15.5,
  pitch: 68,
  bearing: -25
}
3D should explain something

Use mountain relief to discuss terrain or use buildings to discuss urban hazards. Do not add dramatic pitch only because it looks impressive.

Section 11: Change data layers between chapters

Reveal one layer and mute another

Step 11
onChapterEnter: [
  { layer: 'migration-route', opacity: 0.2, duration: 800 },
  { layer: 'stopover-sites', opacity: 1, duration: 800 },
  { layer: 'wetland-habitat', opacity: 0.55, duration: 800 }
],
onChapterExit: [
  { layer: 'stopover-sites', opacity: 0, duration: 500 },
  { layer: 'wetland-habitat', opacity: 0, duration: 500 }
]
  • Use the exact layer ID from Mapbox Studio.
  • Use values between 0 and 1 for opacity.
  • Use duration values in milliseconds.
  • Keep important context visible at reduced opacity rather than turning everything off.
  • Set a layer’s exit state when the next chapter should no longer show it.
The template changes opacity, not arbitrary filters

For a config-only project, create separate Studio layers for categories such as spring observations and fall observations. Then reveal the correct layer in each chapter.

Section 12: Add images, text, and attribution

Keep story assets inside the project

Step 12
  1. Create an images folder inside the Storytelling project.
  2. Optimize each image before adding it. Use an appropriate display size and compressed JPEG or WebP format.
  3. Reference the image with a relative path such as ./images/warbler.jpg.
  4. Keep chapter descriptions brief enough that readers can still see the map.
  5. Add source citations and image credits in the footer or in the relevant chapter descriptions.
  6. Use meaningful link text instead of pasting raw URLs into the visible story.
The template’s image option does not include a separate alt-text field

Inspect the finished output. When accessibility requirements cannot be met through configuration alone, choose images that are supplementary and describe essential information in the chapter text.

Section 13: Test and revise the story

Check map behavior and story clarity

Step 13
  • Scroll forward and backward through every chapter.
  • Confirm that every chapter moves to the intended place.
  • Check that all custom layers appear and disappear at the correct time.
  • Look for layer IDs that are misspelled or use the wrong capitalization.
  • Check the browser console for errors in config.js.
  • Test wide desktop, tablet, and phone widths.
  • Reduce pitch or zoom when the text panel blocks the map feature being discussed.
  • Confirm that the story still makes sense when motion is reduced.
  • Check that the final footer identifies data, map, image, and reporting sources.
Punctuation errors can stop the entire configuration

Check commas between chapters, matching braces and brackets, straight quotation marks, and apostrophes inside quoted text.

Section 14: Publish with GitHub Pages

Publish the complete project folder

Step 14
  1. Create a GitHub repository for the project.
  2. Commit and sync the complete Storytelling folder, including index.html, config.js, supporting scripts, styles, and images.
  3. Open the repository settings and enable GitHub Pages from the main branch.
  4. Open the public Pages URL and test it in a private browser window.
  5. Confirm that the published map loads with your token and custom style.
Publish this as a full page

The Storytelling repository warns that its scroll-driven interface does not work as expected inside an iframe. Link to the full-page project rather than embedding it in another page.
