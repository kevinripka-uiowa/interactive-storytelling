Prompting AI for Custom HTML Blocks

Use this walkthrough when asking AI to write code for an interactive element that will be pasted into a custom HTML block in a builder like Tilda.

Working rule: build the prompt in order. Tell the AI the pattern, where the code will go, what content it should use, how the content should be edited, and how the code should satisfy the 5 As.

Step-by-step prompt walkthrough

Each section below gives students one part of the prompt to fill in. By the end, they should have a complete production prompt.

1

Pattern

Name the type of interactive and describe what the reader does.

Pattern

Prompt section

Create a [accordion / tabs / hotspot annotation / before-after slider / flip cards / filterable cards / stepper / timeline / quiz] that works like this:
[Describe what the reader clicks, taps, selects, or scrolls.]
[Describe what changes on screen.]
2

Production context

This keeps the AI from writing a full web page or global CSS that could interfere with the builder page.

Production context

Prompt section

I will paste this into a custom HTML block in Tilda. Give me a self-contained HTML snippet with embedded CSS and JavaScript. Do not include a full HTML document unless necessary. Scope all CSS to this interactive so it does not affect the rest of the page. Prefer plain HTML, CSS, and JavaScript for simple interactions. Use an external library when it provides a clear advantage for the requested interaction, such as mapping, data visualization, scroll-driven behavior, animation, or 3D content.
3

Content

The AI needs real content or realistic placeholders. Vague prompts usually produce generic interactives.

Content

Prompt section

Use this sample content:
[Paste titles, labels, body text, image filenames, data, credits, etc.]
4

Editable content units

Students should decide whether they want repeated HTML blocks they can copy and paste, or a JavaScript object/array they can edit in one place.

Editable units

Option 1: Repeatable HTML pattern

Best for simple structures such as cards, accordion items, tabs, timeline entries, or hotspot panels.

Option 2: JavaScript object or array

Best for filtering, generated cards, quizzes, steppers, repeated data, or anything easier to update from one organized list.

Option 1 prompt: Repeatable HTML pattern

Make the content easy for a beginner to edit later using a repeatable HTML pattern.

Use clearly commented HTML units that I can copy, paste, delete, or reorder. Each repeated item should have comments showing where one item starts and ends. Use this approach because the content structure is simple, such as cards, accordion items, tabs, timeline entries, or hotspot panels.

Example comment style:
<!-- ITEM 1 START: copy this whole block to add another item -->
<!-- ITEM 1 END -->

Use only this repeatable HTML pattern approach. Do not also create a JavaScript object or array for the content.

Option 2 prompt: JavaScript object or array

Make the content easy for a beginner to edit later using a JavaScript object or array.

Put the editable content in a clearly labeled JavaScript object or array near the top of the script. Use this approach because the interactive has repeated content, filtering, generated cards, step-by-step screens, quiz results, or content that should be easier to update in one place.

Comment the data structure so I know what each field controls. Keep the field names readable, such as title, description, image, alt, category, source, or credit.

Use only this JavaScript object or array approach. Do not also create repeatable HTML content units.
5

Appearance

This is where students describe the visual style, hierarchy, and instructions for the reader.

Appearance

Prompt section

[Describe visual style, hierarchy, colors, spacing, tone, and whether it should match the page.]
Include a clear title for the interactive and a short intro or instructional text that tells the reader how to use it.
6

Asset optimization

AI should not create giant embedded files or depend on random external assets. Students should use replaceable filenames and compressed media.

Asset optimization

Prompt section

Use replaceable image/file names. Do not use base64 assets. Keep the code lightweight. Include placeholders where I should add compressed images, captions, or data.
7

All Devices

Custom HTML-block interactives need to be usable on phones, not just on a laptop preview.

All Devices

Prompt section

Make it responsive for desktop and mobile. Avoid hover-only interactions. Make buttons and controls easy to tap. Stack or simplify the layout on small screens.
8

Accessibility

Students do not need to become ARIA experts, but they should require semantic HTML, keyboard access, focus states, and meaningful labels.

Accessibility

Prompt section

Use semantic HTML. Use real buttons for actions. Make it keyboard accessible. Add visible focus states. Include useful alt text placeholders. Use ARIA only when needed for state or labeling. Do not rely only on color to communicate meaning. Respect reduced-motion preferences.
9

Attribution

Source and credit lines should be part of the interactive, not an afterthought.

Attribution

Prompt section

Include a small readable credit/source line at the bottom.
10

Output

Tell the AI exactly what to return so students can paste the result cleanly into the builder.

Output

Prompt section

Provide only the code I should paste into the custom HTML block.

Debugging prompt

Use this when the code exists but something is broken in the builder or browser.

D

Ask AI to fix a specific problem

Students should describe what is wrong and paste the current code.

Debug

Copy-ready prompt

This code is not working correctly in a Tilda custom HTML block.

Problem:
[Describe what is wrong: buttons do not click, layout breaks, mobile looks bad, modal appears behind other content, etc.]

Context:
It is pasted into a custom HTML block inside a larger Tilda page.

Please:
1. Identify the likely problem.
2. Fix the code.
3. Keep the code self-contained.
4. Keep CSS scoped so it does not affect the rest of the page.
5. Preserve the 5 As: Appearance, Asset optimization, All Devices, Accessibility, and Attribution.

Here is the code:
[paste code]

Revision prompt

Use this when the code works, but the design, mobile behavior, accessibility, or editability needs improvement.

R

Ask AI to improve the working version

This prompt keeps the function intact while asking for a better production version.

Revise

Copy-ready prompt

Revise this interactive code.

Keep the same basic function, but improve it for:
- clearer visual hierarchy
- better mobile layout
- stronger accessibility
- more obvious clickable/tappable controls
- cleaner code comments so a beginner can edit it

Do not add external libraries. Keep it suitable for a Tilda custom HTML block.

Here is the current code:
[paste code]
