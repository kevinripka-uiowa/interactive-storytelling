Explain a Pattern, Process, or Change

Data visualizations and information graphics help viewers understand what is happening, how it varies, how it changes over time, and how parts connect.

Core idea: this module is not just about making charts. It is about choosing the right visual explanation: a focused data pattern, an exploratory data view, a guided story sequence, a timeline, or a diagram.
Chart reference: For chart-type ideas, see the Data Viz Catalogue. Use it to study visual forms, then decide what job the graphic needs to do in the story.

Explanatory Data Visualization

Use this when the author has found the pattern and needs the viewer to understand it clearly. The interaction should support reading the evidence: tooltips, hover/focus highlights, labels, callouts, and guided inspection.

Explanatory Data Visualization

An explanatory data visualization focuses the viewer on one important pattern in the evidence. The chart can still be interactive, but the interaction should help readers inspect values, highlight a data point or set, and understand the author’s main point.

Explain

Story job

Primary: Explain. Also useful for: Compare when interaction highlights differences between groups.

Affordances

Procedural because the chart responds to hover/focus; encyclopedic because exact data values sit behind the visual marks.

Agency

Guided inspection. The author chooses the pattern, while the viewer checks details within the graphic.

Key interactions

  • Tooltip labels for exact values and short context.
  • Hover or keyboard focus to highlight one bar, point, line, or data set.
  • Persistent annotation or callout for the most important pattern.
  • Optional legend hover to isolate one series.
Example: The chart explains one finding: grassland birds show the steepest decline. Hover or focus each bar to read the value.

Good tool fit: Datawrapper chart, Flourish chart, or custom SVG/HTML.

Exploratory Data Visualization

Use these when the dataset is large enough that readers need controlled ways to explore, narrow, filter, sort, or compare. The author still designs the available questions, but the viewer has more agency than in a single explanatory chart.

Filterable data visualization

A filterable data visualization lets viewers narrow a chart by group, habitat, season, place, or status. It is useful when the dataset is larger than one focused view, but the available questions are still bounded.

Explore

Story job

Primary: Explore. Also useful for: Compare when filters help readers isolate groups against one another.

Affordances

Participatory because the reader chooses filters; procedural because the chart redraws; encyclopedic because the dataset contains more than one view.

Agency

Limited exploratory agency. The viewer can ask small questions using author-defined controls.

Key interactions

  • Dropdowns, buttons, or checkboxes to filter the displayed data.
  • Line or mark highlighting when a group is selected.
  • Tooltips that still work after filtering.
  • Clear “show all” state so the viewer can return to the overview.
Example: Filter the line chart by habitat group. The pattern changes from “overall migration reports” to a more specific story about where birds are being observed.

Good tool fit: Flourish filters, Datawrapper with highlighting, or custom HTML/JS chart.

Sort-and-compare view

A sort-and-compare view lets readers reorder the same records by different measures. It works when the main task is comparison: biggest, smallest, fastest, longest, most severe, or most common.

Compare

Story job

Primary: Compare. Also useful for: Explore when sorting becomes a way to browse the dataset.

Affordances

Procedural because order changes; participatory because the reader chooses the sort; encyclopedic because records can be reorganized.

Agency

Limited choice. The viewer controls the comparison order, but the available measures are author selected.

Key interactions

  • Sort buttons or dropdowns for changing the ranking measure.
  • Animated reorder or bar-length change to make the comparison visible.
  • Labels that keep exact values readable without relying only on bar length.
  • Optional hover/focus to explain why a measure matters.
Good tool fit: Flourish cards, sortable table, Datawrapper table, or custom JavaScript.

Guide viewers through data views

Use these when one dataset can answer several related questions. The key is not “more charts.” It is changing the view to change what the viewer can understand.

Revisualization switcher

A revisualization switcher shows the same data in multiple visual arrangements. Each view should answer a different question, such as trend, ranking, category, or seasonal timing.

Compare / Explain

Story job

Primary: Compare and Explain. Each view should reveal a different reading of the same evidence.

Affordances

Procedural because the visualization changes; participatory when readers choose the view; encyclopedic because one dataset supports multiple readings.

Agency

Limited choice or guided, depending on whether the reader switches views or the story advances them.

Key interactions

  • Buttons or tabs that change the analytical view, not just the content panel.
  • Consistent labels so readers understand they are seeing the same data reorganized.
  • Highlighting to keep the same species, group, or pattern visible across views.
  • Short captions that state what each view helps answer.

View 1: reports over the season

This view answers: when do reports peak?

View 2: species ranked by peak reports

This view answers: which species dominate the peak?

View 3: grouped by migration strategy

This view answers: which strategy explains timing?

Good tool fit: Flourish revisualization, Flourish stories, or custom view switcher.

Step-through data story

A step-through data story guides viewers through a sequence of claims. It works when readers need help seeing which part of the data matters first, second, and third.

Explain

Story job

Primary: Explain. Also useful for: Compare when each step contrasts groups or moments.

Affordances

Procedural because the view changes step by step; participatory because the reader controls pace; encyclopedic because each step draws from the same dataset.

Agency

Guided. The viewer advances, but the author controls the order and meaning of the sequence.

Key interactions

  • Next/back or step buttons that move through a planned argument.
  • Highlights that shift to the relevant bar, line, region, or group.
  • Captions that explain what changed in the visual at each step.
  • Optional scroll-driven steps for a more article-like reading flow.
Good tool fit: Flourish stories, Datawrapper locator-style annotations, scrollytelling, or custom HTML/JS.

Explain beyond charts

Information graphics are visual explanations that may use data, labels, sequence, scale, parts, or systems. This section separates the visualization type from the interaction pattern. A type gives the material its structure; interaction controls how viewers inspect, switch, compare, filter, or move through that structure.

Labeled diagrams

Labeled diagrams explain an object, organism, or structure by naming parts and directing attention. The visual type might be simple, exploded, magnified, or cross-section. Students can click each example image to inspect the larger version.

Explain

Story job

Primary: Explain. Also useful for: Compare when different views show different levels of detail or different states.

Affordances

Spatial because labels attach to parts; encyclopedic because each part can hold explanation; procedural when the view, labels, or zoomed details change.

Agency

Guided inspection. The viewer can inspect or switch views, but the author defines the important parts.

Possible interactions

  • Reveal, Explore, Compare Patterns: tooltips, hotspots, rich annotations, tabs, and modals all work well for labeled diagrams.
  • Simple view: use hover/focus labels or clickable hotspots so the diagram stays readable without over-labeling.
  • Exploded view: use layer toggles, part-by-part highlighting, or a stepper to separate and explain hidden structures.
  • Magnified view: use clickable insets, loupe/magnifier behavior, zoom panels, or detail modals for small features.
  • Cross-section: use slice/reveal controls, before/after toggles, scroll-driven cuts, or labeled layers to show what is inside a structure.

Simple view

Keeps the subject intact. Best when viewers need to recognize the whole object and learn visible parts.

Exploded view

Separates parts that normally overlap. Best when structure, assembly, or hidden layers matter.

Magnified view

Uses an inset or zoom to show small features. Best when the critical evidence is too small to see in the full view.

Cross-section diagram

Cuts through a structure to show interior layers. Example: a feather shaft, egg, nest, or wing structure shown from the inside.

Good tool fit: static image from Illustrator/Figma plus hotspots, custom SVG/HTML, Genially, or a page-builder image annotation block.

Visual lists

A visual list organizes examples, categories, or variants so viewers can see what belongs together and what differs. The type of list determines the logic: shared trait, variable differences, variant comparison, scale, or part-to-whole.

Explain / Compare

Story job

Primary: Explain or Compare. Also useful for: Explore when the list becomes searchable, filterable, or browsable.

Affordances

Encyclopedic because lists organize many items; spatial because grouping and ordering create meaning; procedural when sorting, filtering, or expanding changes the list.

Agency

Low to limited exploratory agency. The viewer may scan, filter, sort, expand, or compare items within an author-defined set.

Possible interactions

  • Reveal, Explore, Compare Patterns: flip cards, hover cards, accordions, modals, and master-detail panels work when each item needs more detail.
  • Common denominator: use grouping, hover labels, or category filters to show why items belong together.
  • Common denominator with variables: add color, icon, size, or label changes, then let viewers filter or highlight by the variable.
  • Variant comparison: use tabs, toggles, side-by-side cards, or hover/focus states to compare forms of the same thing.
  • Scale and part-to-whole: use proportional sizing, sliders, tooltips, or animated transitions so viewers can read quantities without losing the object metaphor.

Common denominator

Shows items that share a defining trait. Example: grassland birds grouped because they depend on open prairie habitat.

Common denominator with variables

Shows a shared category plus a variable. Example: grassland birds colored by endangered or not endangered status.

Variant comparison

Shows versions of a particular thing. Example: beak shapes adapted for seeds, insects, nectar, or fish.

Scale comparison

Uses relative size to make magnitude visible. Example: comparing wingspans across species.

Part-to-whole comparison

Shows object parts by proportion. Example: a bird diet graphic showing percent seed, fruit, insects, and nectar.

Good tool fit: Flourish cards, Datawrapper tables, custom HTML/CSS cards, Illustrator/Figma static exports, or a spreadsheet-backed visual list.

System and process diagrams

System and process diagrams explain how something works, how parts relate, or how one condition moves into another. The type can show states of one subject or a sequence of actions, causes, and effects.

Explain

Story job

Primary: Explain. Also useful for: Compare when the same system is shown before/after, healthy/unhealthy, or normal/problem/intervention.

Affordances

Spatial because relationships are arranged visually; procedural when stages advance; encyclopedic because each state or step can carry additional explanation.

Agency

Guided or step-driven. The viewer follows the logic of the system and may inspect parts or move through steps.

Possible interactions

  • Reveal, Explore, Compare Patterns: rich annotations, button-guided focus, tabs, layer toggles, and scrolly focus can all guide system diagrams.
  • State comparison: use toggles, before/after states, side-by-side comparison, or step buttons to show one thing in different conditions.
  • Process diagram: use next/back controls, animated path highlighting, cause-effect reveals, or scroll-driven steps to pace the workflow.
  • System-specific: dependency highlighting, node inspection, layer controls, and “show intervention” toggles help explain how parts affect one another.

State comparison

Shows the same subject in different conditions. Example: a prairie wetland before, during, and after restoration.

Process diagram

Shows a sequence of causes, actions, or decisions. Example: how window reflection creates collision risk and how treatments reduce it.

Good tool fit: custom SVG/HTML, Genially, Flourish story cards, Illustrator/Figma export plus annotation layers, or page-builder step sections.

Timelines and time flows

Timelines explain when things happen. Time flows move closer to data visualization by showing rhythm, duration, accumulation, intensity, or seasonal pattern across time.

Explain / Compare

Story job

Primary: Explain. Also useful for: Compare when species, places, years, or stages are placed side by side.

Affordances

Spatial because time is arranged visually; procedural when readers step, scroll, scrub, or animate; encyclopedic because each event or time period can hold detail.

Agency

Guided to exploratory. A simple timeline guides the viewer; a time flow can let the viewer scrub, filter, or compare patterns.

Possible interactions

  • Reveal, Explore, Compare Patterns: horizontal overflow, vertical overflow, slideshows, accordions, and scrolly focus work well for timelines.
  • Normal timeline: use step-through controls, event modals, expandable entries, or scroll-based focus to reveal details in order.
  • Time flow: use scrubbers, sliders, autoplay, date filters, and hover tooltips to make rhythm, intensity, or accumulation readable.
  • Comparative time: add species filters, group highlighting, or small multiples when readers need to compare timing across groups.

Normal timeline

Uses ordered events. Example: a Bobolink breeding season from arrival to migration.

Time flow

Shows intensity, volume, or pattern across time. Example: migration reports rising and falling by month.

Good tool fit: Flourish timeline/story, Datawrapper line chart or locator chart, custom HTML/SVG, or illustrated sequence with scroll/step controls.
