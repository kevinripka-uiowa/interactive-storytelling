Prompting AI for Custom Interactives

Use this walkthrough when asking AI to write a full custom interactive that will live as its own web page, be hosted on GitHub Pages, and be placed inside a story page with an iframe.

Working rule: this is not a custom HTML-block snippet. Ask for a complete index.html file with the full HTML wrapper, viewport setup, scoped code, replaceable assets, and an iframe-friendly layout that fills the available space.

Step-by-step prompt walkthrough

Each section below gives students one part of the prompt to fill in. By the end, they should have a complete production prompt for a GitHub-hosted interactive.

1

Pattern

Name the type of interactive and describe what the reader does.

Pattern

Prompt section

Create a [filterable explorer / scrolly explainer / interactive map / timeline / quiz / guided comparison / data visualization / image annotation / step-by-step process] that works like this:
[Describe what the reader clicks, taps, selects, scrolls, drags, or enters.]
[Describe what changes on screen.]
2

Production context

This tells AI that the project is a complete web page for GitHub Pages, not a snippet for a builder block.

Production context

Prompt section

This interactive will be hosted as a standalone page on GitHub Pages and embedded in a larger story page using an iframe.

Give me a complete index.html file with the full HTML wrapper, including <!DOCTYPE html>, <html>, <head>, <meta name="viewport">, <body>, CSS, and JavaScript.

Use only front-end code that can run on GitHub Pages: HTML, CSS, and JavaScript. Do not use server-side code. Do not require a build process unless I specifically ask for one. Do not use external libraries unless there is a strong reason.
3

Iframe behavior

The embedded page should fill the iframe. The parent page controls the iframe size, so the interactive should not assume a fixed width or height.

Iframe fit

Prompt section

Design the page so it works well inside an iframe.

The visualization should take up the full available iframe width and height. Set html and body to width: 100%, height: 100%, and margin: 0. Use a main interactive container that can fill the viewport, such as min-height: 100vh or height: 100vh when appropriate.

Do not set a fixed pixel width for the full interactive. Let the parent iframe control the displayed size. Avoid unnecessary outer page margins. If the interactive needs scrolling, make the scrolling intentional and testable inside the iframe.
4

Content

The AI needs the actual labels, descriptions, image filenames, data, and credits that the interactive will use.

Content

Prompt section

Use this sample content:
[Paste titles, labels, body text, image filenames, data, categories, captions, source notes, credits, etc.]

Use relative paths for assets I will upload with the GitHub project, such as assets/image-name.jpg or data/example.csv.
5

Editable content units

Students should decide whether they want repeated HTML blocks they can copy and paste, or a JavaScript object/array they can edit in one place.

Editable units

Option 1: Repeatable HTML pattern

Best for simple structures such as cards, timeline entries, panels, slides, or annotation sections.

Option 2: JavaScript object or array

Best for filtering, generated cards, quizzes, maps, charts, steppers, or larger datasets.

Option 1 prompt: Repeatable HTML pattern

Make the content easy for a beginner to edit later using a repeatable HTML pattern.

Use clearly commented HTML units that I can copy, paste, delete, or reorder. Each repeated item should have comments showing where one item starts and ends.

Example comment style:
<!-- ITEM 1 START: copy this whole block to add another item -->
<!-- ITEM 1 END -->

Use only this repeatable HTML pattern approach. Do not also create a JavaScript object or array for the content.

Option 2 prompt: JavaScript object or array

Make the content easy for a beginner to edit later using a JavaScript object or array.

Put the editable content in a clearly labeled JavaScript object or array near the top of the script. Use this approach because the interactive has repeated content, filtering, generated cards, a map, a chart, step-by-step screens, quiz results, or content that should be easier to update in one place.

Comment the data structure so I know what each field controls. Keep the field names readable, such as title, description, image, alt, category, latitude, longitude, value, source, or credit.

Use only this JavaScript object or array approach. Do not also create repeatable HTML content units.
6

Appearance

This is where students describe the visual style, hierarchy, and instructions for the reader.

Appearance

Prompt section

[Describe visual style, hierarchy, colors, spacing, tone, and whether it should match the larger story page.]

Include a clear title for the interactive and a short intro or instructional text that tells the reader how to use it. Keep the interface clean enough to work inside an iframe without feeling cramped.
7

Asset optimization

GitHub Pages can host static assets, but students still need clean file paths and lightweight media.

Asset optimization

Prompt section

Use replaceable image/file names with relative paths, such as assets/photo-1.jpg or data/items.csv. Do not use base64 assets. Do not use random external image URLs.

Keep the code lightweight. Include placeholders where I should add compressed images, captions, transcripts, or data files. If you include sample data inside the JavaScript, make it easy to replace later.
8

All Devices

The interactive needs to work both as a standalone GitHub page and inside an iframe at different sizes.

All Devices

Prompt section

Make it responsive for desktop and mobile. Avoid hover-only interactions. Make buttons and controls easy to tap.

The layout should adapt to different iframe widths and heights. On small screens or short iframe heights, stack or simplify the layout. Do not let important controls disappear outside the visible iframe area.
9

Accessibility

Students should require semantic HTML, keyboard access, visible focus states, alt text, and careful motion.

Accessibility

Prompt section

Use semantic HTML. Use real buttons for actions. Make it keyboard accessible. Add visible focus states. Include useful alt text placeholders.

Use ARIA only when needed for state or labeling, such as expanded panels, selected tabs, or modal labels. Do not rely only on color to communicate meaning. Respect reduced-motion preferences.
10

Attribution

Credits and source notes should remain visible in the standalone interactive.

Attribution

Prompt section

Include a small readable credit/source line inside the interactive. Use placeholder text such as Source: [source name]. Images: [credit]. Code assistance: AI used for drafting/debugging.
11

Output

Tell the AI to return the complete file only.

Output

Prompt section

Provide the complete code for index.html.

Debugging prompt

Use this when the GitHub-hosted page or iframe embed is not working correctly.

D

Ask AI to fix a specific problem

Students should describe whether the problem happens on GitHub Pages, inside the iframe, or both.

Debug

Copy-ready prompt

This custom interactive is not working correctly as a GitHub-hosted page and/or iframe embed.

Problem:
[Describe what is wrong: blank iframe, file paths broken, buttons do not click, layout does not fill iframe, page has unwanted margins, mobile layout breaks, scrolling is awkward, images do not load, etc.]

Context:
The interactive is a standalone index.html file hosted on GitHub Pages and embedded in a larger story page using an iframe.

Please:
1. identify the likely problem,
2. fix the code,
3. keep it as a complete index.html file,
4. preserve the full HTML wrapper,
5. keep the layout iframe-friendly with full-width and full-height behavior,
6. use relative asset paths suitable for GitHub Pages,
7. preserve the 5 As: Appearance, Asset optimization, All Devices, Accessibility, and Attribution.

Here is the code:
[paste code]

Revision prompt

Use this when the interactive works but needs better design, editing structure, mobile behavior, or iframe fit.

R

Ask AI to improve a working version

This prompt is for improving quality without changing the basic concept.

Revise

Copy-ready prompt

Revise this GitHub-hosted custom interactive.

Keep the same basic function, but improve it for:
- clearer visual hierarchy,
- better iframe fit,
- better full-width and full-height behavior,
- better mobile layout,
- stronger accessibility,
- more obvious clickable/tappable controls,
- cleaner beginner-friendly comments,
- easier content editing.

Keep it as a complete index.html file with the full HTML wrapper. Do not add external libraries unless there is a strong reason. Keep it suitable for GitHub Pages and iframe embedding.

[paste code]
