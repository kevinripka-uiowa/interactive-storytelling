Interactive storytelling reference

Turn a vector graphic into an interactive explainer

An SVG can be more than a scalable illustration. Because its shapes and groups can exist as elements in the page, you can make individual parts clickable, reveal information, change states, respond to scrolling, or connect a designed graphic to story text.

Core idea: use SVG when the graphic itself is part of the explanation. Instead of treating an illustration as a flat image, make meaningful parts of it respond to the user.

Why interactive SVG is useful

Interactive SVG sits between simple HTML/CSS interactions and heavier libraries such as D3, Leaflet, or Three.js. Use it when the graphic itself is part of the explanation, especially for diagrams, custom maps, process graphics, and designed illustrations.

A productive middle ground

You can create a custom visual experience without building every shape in JavaScript or adopting a large visualization framework.

Why it matters
1

Design first

Create the visual structure in Illustrator or another vector tool, then add interaction to meaningful parts.

2

Target parts directly

JavaScript can select one path, shape, label, or group and change only that part of the graphic.

3

Explain through states

Use clicks, buttons, filters, or scrolling to highlight different stages, systems, regions, or components.

Good fit: anatomy diagrams, process graphics, floor plans, campus maps, historical maps, systems diagrams, technical explainers, and scroll-driven illustrations.

How SVG works

SVG stands for Scalable Vector Graphics. Instead of storing a grid of pixels, SVG markup describes graphic elements such as circles, rectangles, text, paths, and groups.

SVG is made of elements

A browser can treat graphic parts as individual elements, much like headings, buttons, and sections in HTML.

Structure 
<svg viewBox="0 0 800 500">
  <circle
    cx="200"
    cy="200"
    r="50"
  ></circle>

  <rect
    x="350"
    y="150"
    width="120"
    height="100"
  ></rect>

  <path d="..."></path>
</svg>
  • <circle> draws a circle.
  • <rect> draws a rectangle.
  • <path> can describe complex vector shapes.
  • <g> groups multiple graphic elements together.
  • id and class let CSS and JavaScript target important parts.

A PNG is pixels. An inline SVG is structure.

This is the distinction that makes interactive SVG possible.

Mental model

Raster image

A PNG or JPEG is essentially a field of pixels. The browser does not know that one cluster of pixels is a wing and another is a bill.

Inline SVG

The browser can know that one element has id="bill", another has id="wing", and a group has id="migration-route".

Production workflow: Illustrator to interactive SVG

A practical SVG workflow lets you begin with a familiar visual design process and then add interactivity.

A practical workflow

Design the graphic first, but organize it so meaningful parts can be targeted later.

Production
1

Design

Create the illustration, diagram, or map in Illustrator.

2

Organize

Put meaningful parts on separate layers or groups.

3

Name

Give important layers clear names such as river, factories, bill, wing, or step-1.

4

Export

Export the artwork as SVG.

5

Inline

Place the SVG markup inside the HTML page.

6

Connect

Use CSS and JavaScript to change meaningful groups and states.

Groups make complex graphics manageable

A single logical part of the illustration may contain many paths. Group them so your code can target the whole concept at once.

SVG groups 
<g id="river">
  ...
</g>

<g id="factories">
  ...
</g>

<g id="railroads">
  ...
</g>

<g id="neighborhoods">
  ...
</g>
Working rule: name layers by meaning, not appearance. factories is more useful than blue-shapes.

Expect some cleanup after export

Illustrator may produce long paths, generated class names, and layer names that are difficult to read.

Reality check 
<g id="Layer_2_0000012631504809">
  <path
    class="st17"
    d="M382.72,173.91c..."
  />
</g>
Student strategy: preserve the important groups and IDs, but do not expect exported SVG code to look as clean as hand-written HTML.

Inline SVG vs. an SVG image file

This is the most important implementation distinction. Displaying an SVG file is not the same as putting its internal elements into the page DOM.

Use an image when you only need to display it

This is simple and appropriate for a non-interactive vector image.

Display only 
<img
  src="bird.svg"
  alt="Diagram of a bird"
>

Use inline SVG when you need to target internal parts

The SVG markup becomes part of the page, so CSS and JavaScript can directly select its elements.

Interactive 
<svg viewBox="0 0 800 500">
  <path
    id="bill"
    d="..."
  ></path>
</svg>
Core distinction: <img src="bird.svg"> displays the SVG as an image. Inline <svg>...</svg> lets page JavaScript directly target internal elements such as #bill.

Responsive SVG

SVG scales well, but students need one core concept: the viewBox.

The viewBox defines the internal coordinate space

The browser can scale that coordinate space to fit the available width.

All devices 
<svg
  viewBox="0 0 800 500"
  width="100%"
>
  ...
</svg>
  • 0 0 is the starting coordinate.
  • 800 500 describes the internal width and height.
  • width="100%" lets the SVG fit the available container.
  • The artwork can scale while preserving its internal geometry.
Working rule: test labels, hotspots, and touch targets at phone sizes. A graphic can technically scale while still becoming too dense to use.

Accessibility

A clickable SVG shape is not automatically an accessible control. Mouse interaction alone is not enough.

Prefer robust controls for important interaction

One reliable pattern is to let real HTML buttons control the SVG state.

Accessibility 
<button
  type="button"
  data-part="bill"
>
  Bill
</button>
<path
  id="bill"
  d="..."
></path>

Keyboard access

Users should be able to reach and activate important controls without a mouse.

Visible focus

Keyboard users need to see which control is currently active.

Equivalent information

The explanation should not depend only on color, hover, or precise pointer movement.

Hybrid approach: the SVG can still respond to direct clicks, but visible buttons can provide a clearer and more accessible control system.

Interaction patterns

Once your SVG is organized and inline in the page, you can connect it to several common storytelling patterns. Start with the simplest interaction that fits the explanation.

Pattern 1: clickable parts of an illustration

One of the strongest uses is a diagram where the user selects a meaningful part and the page reveals an explanation.

Example: explore the anatomy of a bird

Different SVG shapes can act as targets for information about feeding, flight, habitat, or identification.

Reveal + Explain 
<svg viewBox="0 0 800 500">
  <path
    id="wing"
    d="..."
  ></path>

  <path
    id="bill"
    d="..."
  ></path>
</svg>
const bill =
  document.querySelector("#bill");

bill.addEventListener("click", () => {
  document.querySelector(
    "#info-panel"
  ).innerHTML = `
    <h2>Bill</h2>
    <p>
      This shape is adapted
      for probing flowers.
    </p>
  `;
});

Simple example

Click the orange bill or green wing.

Story use: anatomy, machinery, architecture, ecological systems, camera controls, scientific diagrams, and any illustration with meaningful components.

Pattern 2: custom maps that do not need a mapping library

Some projects look geographic but do not need map tiles, panning, zooming, or live coordinates. A designed SVG can be simpler and more appropriate.

Use SVG when the map is really an explanatory graphic

A campus plan, floor plan, festival layout, historical map, or illustrated region may work better as a designed vector graphic.

Locate + Compare

Good SVG map uses

Campus buildings, neighborhoods, historical districts, migration flyways, event grounds, room layouts, watersheds, and schematic routes.

Use Leaflet or Mapbox when

The user needs geographic navigation, map tiles, accurate coordinate placement, dynamic spatial layers, or pan-and-zoom exploration.

<path
  id="downtown"
  class="district"
  d="..."
></path>

<path
  id="west-side"
  class="district"
  d="..."
></path>

<path
  id="riverfront"
  class="district"
  d="..."
></path>

Simple example

Click a district to identify it.

Pattern 3: show change through visual states

An SVG can stay in one place while JavaScript changes classes that reveal, hide, fade, or highlight parts of the graphic.

Example: show a landscape over time

Buttons or a stepper can move between historical states without rebuilding the graphic.

Compare + Change 
graphic.classList.add(
  "year-1950"
);
.year-1950 .railroad {
  opacity: 1;
}

.year-1950 .wetland {
  opacity: 0.3;
}

Simple example

Choose a year.

Useful for: land-use change, infrastructure growth, ecological change, architecture, political boundaries, historical development, and process stages.

Pattern 4: interactive process diagrams

SVG is effective when a story needs to explain how something moves through a system or how several components relate.

Let the user move through a system

Each step can highlight a section of the diagram, reveal detail, animate a flow, or update explanatory text.

Explain a process
  • Source → where something begins.
  • Processing → how it changes.
  • Distribution → how it moves.
  • Consumer → where it ends or who experiences the result.

Click

Users select a step and control the pace of explanation.

Stepper

Next and previous buttons create a guided sequence.

Scroll

The graphic changes as the reader moves through explanatory text.

Simple example

Choose a step to highlight it.

Pattern 5: scroll-driven SVG

A persistent SVG can change as the user scrolls through a sequence of explanatory text. This is one of the strongest combinations for interactive journalism.

One graphic, multiple explanatory states

The page can highlight a different part of the same SVG at each scroll step.

Guided interaction

Step 1

Show the overview and establish the full system.

Step 2

Highlight the river and explain its role.

Step 3

Reveal factories and explain industrial growth.

Step 4

Show transportation and population movement.

graphic.classList.remove(
  "step-1",
  "step-2",
  "step-3"
);

graphic.classList.add("step-2");
